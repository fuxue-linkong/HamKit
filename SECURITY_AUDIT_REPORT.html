✅ 安全亮点

🔐 加密实现

敏感数据（API Keys、会话历史）使用 AES-256-GCM 加密，私钥通过 Android Keystore 妥善管理，不出硬件。实现完全符合 NIST 标准。

🛡️ 网络安全

网络安全配置严格：禁止明文流量、仅信任系统 CA、自签证书限制为私网地址。业务层代码强制验证确保即使 manifest 放开某些权限也不会被滥用。

🔑 签名密钥管理

Release 签名通过环境变量注入，无签名时构建强制失败。防止了 debug keystore 被用于发布正式版的致命风险。

🚀 CI/CD 安全

GitHub Actions 流程遵循最小权限原则、使用 GitHub Secrets 管理敏感信息、产物通过 artifact 管理而不提交回仓库。无泄露风险。

📋 版本管理

第三方依赖版本锁定（如高德地图从浮动版本锁定为 10.0.600），确保构建可复现性，防止上游污染。

🔍 权限原则

AndroidManifest 声明的权限都有明确的业务用途：位置（定位功能）、麦克风（FT8 解码）、通知（日程提醒），无过度权限申请。

⚠️ 发现的问题

中优先级 (1 项)

明文 HTTP 的私网限制需增强验证
MEDIUM
位置： app/src/main/java/com/example/hamkit/data/ai/AiNetworkPolicy.kt

问题描述： 明文 HTTP 仅限私网地址的验证依赖于正则表达式匹配。虽然正则本身正确，但存在以下边界情况风险：
  • IPv6 地址不在验证范围内（仅检查 IPv4）
  • 主机名解析（如 internal.corp 可能意外路由到公网）未做 DNS 反查验证
  • 若用户在主机名字段输入 IP 地址的十进制形式（如 2130706433 等价 127.0.0.1），当前不认识
建议：
  • 添加 IPv6 私网范围验证（fc00::/7、fe80::/10、::1）
  • 使用 InetAddress.getByName() 进行 DNS 解析并验证结果 IP 是否私网
  • 拒绝十进制 IP 表示（仅接受标准 dotted-decimal 形式）
  • 优先级：下个 Sprint 改进

结论： 所有依赖版本都是最新的主流版本，无已知高危 CVE。

代码安全

已扫描 409 个 Kotlin 源文件：

  • 硬编码密钥： ✓ 未发现任何硬编码的 API key、密码或 token
  • SQL 注入： ✓ 所有数据库操作使用 Room DAOs 的参数化查询
  • 不安全日志： ✓ 未发现在日志中输出敏感信息
  • 反序列化： ✓ 未使用 ObjectInputStream，使用 Kotlin serialization 和 Room（安全）
  • 路径遍历： ✓ 文件操作通过 FileProvider，限制在应用私有目录

数据存储

使用的存储机制：

  • API Keys & 会话： AES-256-GCM 加密（AiCrypto.kt）+ Android Keystore
  • QSO 日志： Room SQLite 数据库，位置：/data/data/com.example.hamkit/databases/
  • 设置与偏好： DataStore（androidx.datastore），加密支持可选
建议： DataStore 的敏感字段（如 MCP token）也应使用加密，参考 AiCrypto 的模式。

网络通信

网络安全配置：

  • HTTPS： 强制使用系统 CA，无自签证书降级（除非用户在 AI 设置中显式开启内网模式）
  • HTTP： manifest 禁止，业务层代码再次验证目标地址是私网
  • 自签证书： 仅限私网地址，代码级强制验证（AiHttp.resolve）
  • TLS 版本： OkHttp 5.3 默认 TLS 1.2+，无落后协议

权限与导出组件

已审查所有 AndroidManifest 声明：

  • 导出 Activity： MainActivity 导出（启动器需要），无深链接 intent-filter
  • 导出 Service： MediaProjectionService 导出（系统服务需要），其他服务 exported=false
  • 导出 BroadcastReceiver： ReminderBootReceiver 导出，处理 BOOT_COMPLETED 事件，输入安全（系统 intent）
  • FileProvider： exported=false，权限通过 intent 授予

结论： 所有导出组件都有明确的业务用途，无 intent-filter 可被滥用的深链接。

Build & CI/CD 安全

GitHub Actions 工作流分析：

  • 权限： Job 级别 contents: read（最小必需）
  • 密钥管理： 使用 GitHub Secrets（KEYSTORE_BASE64、AMAP_SDK_KEY 等），不在日志中暴露
  • 产物管理： artifact 上传，保留 30 天，不提交回仓库
  • 签名验证： 构建完成后用 apksigner 验证 v2 签名，输出 SHA-256 指纹
  • 并发控制： 同分支新推送自动取消旧运行（节省额度）
