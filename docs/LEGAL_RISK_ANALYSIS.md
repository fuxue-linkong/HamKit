# HamKit 法律风险分析报告

> 分析对象：`Dual-zone_network_positioning`（Android 应用 HamKit + `website/` 官网 + APK 分发链路）
> 分析时间：2026-10-18
> 性质：技术—合规风险分析，**不构成正式法律意见**。正式发布、上架、商业化前，建议由熟悉无线电、个人信息保护与互联网信息服务的中文执业律师，结合运营主体、服务器所在地、用户分布出具正式意见。
>
> **2026-10-21 已实施（部分）**：App 首启隐私政策/同意、高德 SDK 延后到同意后初始化、`allowBackup=false`；移除 `secrets.dat`/`SecretManager`/三碎片方案，地图 SDK 与 Web 服务（天气/逆地理编码）仍全部使用高德，Web Key 构建时写入 `BuildConfig`；官网新增 `/privacy.html` 并从首页/登录/用户中心链接，用户中心支持导出/注销账号；`FIRST_USER_IS_ADMIN` 默认 false、支持 `OIDC_REQUIRE_MFA`；release 构建禁止 debug keystore 兜底；更新链增加 CDN 域名白名单、SHA-256 与 APK 签名/包名/版本号校验；官网发布 API 强制官方 CDN + 64 位 SHA-256。仍需人工完成：限制/监控高德 Key 并清理 git 历史、App 备案/ICP、FT8 发射门控与执照类别校验。

## 一、结论摘要

HamKit 不是“单纯的离线工具软件”。它同时具备以下法律身份：

1. **处理行踪轨迹等敏感个人信息的 App**（定位、地图、天气、APRS）；
2. **通过互联网提供服务的 App**（天气、TLE、AMSAT、APRS-IS、在线更新），涉及 App 备案；
3. **具备 FT8 / SSTV 音频发射能力**、并向用户展示卫星上行频率的业余无线电辅助工具；
4. **内嵌高德地图 SDK 的地图类应用**（还可能构成互联网地图服务）；
5. **通过自建官网 / GitHub 分发 APK 的发布者**；
6. **包含大量第三方代码、数据、图片的开源项目**。

因此，风险不是单点的，而是“**无线电 + 个人信息 + 互联网信息服务 + 地图测绘 + 开源许可 + 供应链**”六条线叠加。按“可能性 × 后果”排序，最需要先处理的是：

| 优先级 | 风险 | 一句话结论 |
|---|---|---|
| **P0** | 个人信息保护 | App 没有隐私政策、没有首启同意，却把高德 SDK 的“已同意”写死为 true，并处理精确位置、麦克风、录屏音频 |
| **P0** | App 备案 / ICP | App 和官网均未见备案号；App 内也没有展示备案编号 |
| **P0** | 高德 Key 与“加密”方案 | 明文 Key 已进入 git 跟踪的文档；所谓三碎片加密在公开仓库里可完整还原 |
| **P0** | FT8“允许发射”开关 | 开关只改配置，不拦截编码/播放；未持照用户可能“以为没开”却实际把信号送进电台 |
| **P0** | 签名与更新链 | 无 release keystore 时静默回退 debug 签名；更新 APK 不校验 SHA-256/签名；官网后台可填任意下载地址 |
| **P1** | 数据出境 | 官网/对象存储在境外，App 还可能把位置、呼号、日志备份到境外云 |
| **P1** | 开源与数据许可 | Apache/ISC/MIT 无 NOTICE；SatNOGS/CelesTrak 无署名；图片 `the_moon.jpg` 来源不明 |
| **P1** | 网站个人信息与后台安全 | 无隐私政策/用户协议；首个登录者即管理员；无 MFA；管理员可推送任意 APK |
| **P2** | 地图测绘 | 叠加 APRS/卫星轨迹的地图，可能被认定为互联网地图服务，涉及测绘资质/审图号 |
| **P2** | 免责条款与产品责任 | “一切后果由用户承担”在人身损害/重大过失情形下很可能无效 |
| **P2** | 商店与分发政策 | `REQUEST_INSTALL_PACKAGES`、`USE_EXACT_ALARM`、`hiddenapibypass`、`com.example` 包名，Play/国内商店/ F-Droid 均可能拒绝 |

**如果只做五件事：**

1. 立即轮换高德 Key，清理 git 历史，停止把 Key 当“加密资产”宣传；
2. 上线隐私政策 + 首次启动同意 + 高德 SDK 延后到同意之后初始化；
3. 办理 App 备案，并在 App “关于”页展示备案编号；
4. 修复 FT8 发射开关，增加“执照类别 / 频段 / 功率 / 呼号”四道校验；
5. 禁止 debug keystore 兜底，更新包校验 SHA-256 与签名，限制下载域名。

## 二、事实基础

### 2.1 功能与数据流

| 功能 | 数据 | 去向 | 风险点 |
|---|---|---|---|
| 分区定位 / 网格 / 地图 | 精确 GPS 坐标、地址 | 本地；高德地图 SDK + Web 服务（天气/逆地理编码，境内） | 行踪轨迹属于敏感个人信息；无隐私政策 |
| 卫星过境预测 | TLE、观测者坐标 | TLE 来自 `tle.hamkit.click`（文档写明 S3 `ap-east-2` 台北）；预测在本地 | TLE 数据再分发许可；境外对象存储 |
| SatNOGS 转发器库 | 卫星/频率数据 | `db.satnogs.org` API，本地缓存 | CC BY-SA 署名/共享义务 |
| AMSAT 状态 | 状态网页/API | `amsat.org`，本地缓存 | 网页抓取条款、署名 |
| APRS | 呼号、SSID、Passcode、精确位置、消息 | `china.aprs2.net:14580`，原始 TCP；用户可改服务器 | 明文传输；Passcode 明文存储；位置公开 |
| FT8 | 呼号、网格、音频 | 麦克风输入；扬声器播放 | 发射合规、开关失效、频段越权 |
| SSTV / WEFAX | 麦克风/播放捕获音频、图片 | 本地图库、分享 | 录音/录屏隐私；发射呼号可选 |
| QSO 日志 | 呼号、网格、频段、时间 | 本地 Room；ADIF/XML 导出 | 第三方个人信息；云备份 |
| 官网账号 | 邮箱、显示名、头像、IP、会话 | 境外服务器；OIDC | 无隐私政策；数据出境；无注销/导出 |
| 在线更新 | 版本号、下载地址、IP/UA | `hamkit.click`、`apk.hamkit.click`、GitHub | 更新链完整性；境外传输 |

### 2.2 分发形态

- 仅 GitHub Releases + 官网 `hamkit.click` / `apk.hamkit.click` 分发，未见 Google Play / F-Droid / 国内商店上架。
- 包名 `com.example.hamkit`（`app/build.gradle.kts`），Play 通常不接受 `com.example.*`。
- `AndroidManifest.xml` 声明 `REQUEST_INSTALL_PACKAGES`、`USE_EXACT_ALARM`、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 等受限权限。
- 本地 release APK 实测由自定义证书签名（`CN=RadioAreaLocator`），但构建脚本仍保留 debug keystore 静默兜底。

### 2.3 已经做对的合规措施（应保留）

- APRS-IS：已删除本地 Passcode 计算，未填写时 `pass -1` 只读连接，发送路径客户端拦截；首次连接前持照声明。见 `docs/APRS_IS_COMPLIANCE.md`。
- SSTV 发射页有“持照/频率/功率”提示，且不自动开始。
- APRS 位置上报默认关闭（`enableTransmit=false`）。
- 官网 OIDC 使用授权码 + PKCE + state + nonce，JWT 校验较完整；有 CSRF、CSP、路径穿越防护。
- 无广告、无付费、无商业利用，降低了“业余电台不得谋取商业利益”的风险。
- 有免责声明与“卫星数据仅供参考”的表述。

## 三、高风险详析

### 3.1 个人信息保护：目前最大的行政监管敞口（P0）

#### 事实

- `AndroidManifest.xml` 申请 `ACCESS_FINE_LOCATION`、`RECORD_AUDIO`、`FOREGROUND_SERVICE_LOCATION`、`FOREGROUND_SERVICE_MEDIA_PROJECTION` 等。
- `HamKitApplication.kt:99-100` 在 `onCreate()` 中直接调用：
  - `MapsInitializer.updatePrivacyShow(this, true, true)`
  - `MapsInitializer.updatePrivacyAgree(this, true)`
  
  即在**用户尚未看到任何隐私政策、尚未点击同意**之前，就向高德 SDK 声明“已展示、已同意”。
- App 内没有隐私政策、用户协议、第三方 SDK 清单。`AboutScreen` 只有“免责声明”和“开源许可”，没有隐私入口。
- `allowBackup="true"`（`AndroidManifest.xml:55`），而 `backup_rules.xml` / `data_extraction_rules.xml` 是模板，未排除任何数据。默认云备份会包含：
  - `aprs_settings`（呼号、Passcode 明文，见 `AprsSettingsStore.kt:19-21`）；
  - Room 数据库（APRS 站点/消息、QSO 日志）；
  - 设置、图库、录音等。
- APRS 位置上报是“向公众发布精确位置”，但持照声明只写了“你呼号下的流量由你负责”，没有明确告知“位置会公开”。
- 没有个人信息保护影响评估（PIPIA）、没有数据主体权利入口（查阅/复制/更正/删除/撤回同意）、没有未成年人年龄门槛、没有数据泄露通知流程。

#### 法律依据

- 《个人信息保护法》：
  - 第 4 条（个人信息定义）；
  - 第 13、14 条（合法性基础与同意）；
  - 第 17 条（告知义务）；
  - 第 23 条（向第三方提供）；
  - 第 28、29 条（行踪轨迹属于敏感个人信息，需**单独同意**）；
  - 第 30 条（敏感个人信息的额外告知）；
  - 第 31 条（不满十四周岁未成年人）；
  - 第 38、39 条（跨境提供）；
  - 第 51 条（安全措施）；
  - 第 55 条（PIPIA）；
  - 第 57 条（泄露通知）；
  - 第 66 条（最高 5000 万元或上一年度营业额 5%，责任人最高 100 万元，可责令暂停/吊销）。
- 《App 违法违规收集使用个人信息行为认定方法》（2019）：未公开隐私政策、未经同意收集、未经同意向第三方提供、强制/捆绑同意、不提供删除/更正功能等，均可被通报。
- 《常见类型移动互联网应用程序必要个人信息范围规定》（2021）：定位类必要信息可含位置，但不得收集与功能无关的信息；不得因拒绝非必要授权而拒绝基本功能。
- 《移动互联网应用程序信息服务管理规定》（2022）：App 提供者应履行信息内容、用户信息保护、未成年人保护等义务。
- 高德《SDK 合规使用方案》明确要求：**调用 SDK 任何接口前，先按隐私政策取得用户同意，再调用 `updatePrivacyShow` / `updatePrivacyAgree`**。当前写法与该要求相反。

#### 可能后果

- 工信部/网信办通报、责令整改、下架；应用商店拒绝上架或下架。
- 监管罚款；负责人个人罚款。
- 用户民事索赔（尤其是位置、Passcode、QSO 日志泄露）。
- 高德侧：SDK 合规校验失败（errorCode 555570）、服务被停用；若认定开发者虚假声明，可能触发合同责任。

#### 整改清单（建议两周内）

1. 增加首启隐私弹窗：明确列出定位、麦克风、录屏音频、APRS 公开位置、第三方 SDK（高德、Google Play Services Location 如适用）、数据出境情况；用户同意前不初始化高德、不请求定位、不读麦克风。
2. 隐私政策中英文版本，App 内可随时打开；写明处理目的、方式、种类、保存期限、第三方共享、跨境、用户权利、联系方式。
3. 对“行踪轨迹”和“向境外提供”做**单独同意**，不得与一般隐私政策捆绑。
4. 高德初始化移到同意之后；删除硬编码的 `true, true`。
5. `allowBackup=false`，或在备份规则中排除 `aprs_settings`、Room 数据库、录音/图库；Passcode 用 Android Keystore 加密存储。
6. 提供“删除我的数据 / 导出我的数据 / 撤回同意”入口；明确留存期限。
7. 做一次 PIPIA（敏感信息 + 跨境），留存至少 3 年。
8. APRS 开启上报前二次确认：“你的精确位置将公开到 APRS-IS 及关联网站”。
9. 若面向未成年人：增加年龄门槛与监护人同意流程。

### 3.2 App 备案与 ICP：没有备案号，属于“不得从事服务”的硬门槛（P0）

#### 事实

- App 内没有任何备案编号；全仓搜索“备案 / ICP”只在官网后台的页脚编辑字段里出现。
- 官网 `index.html` 页脚默认是 `© 2026 HamKit · MIT License`，`footer.icp` 为空；没有隐私政策、用户协议页面。
- 官网/对象存储部署在境外：`docs/RELEASE_LOCAL.md:54-58` 写明 APK bucket 为 `hamkit-apk-tpe`（`ap-east-2`，台北），CloudFront 别名 `apk.hamkit.click`，官网服务器为境外 IP。
- App 提供天气、TLE、AMSAT、APRS-IS、在线更新等互联网信息服务。

#### 法律依据

- 工信部《关于开展移动互联网应用程序备案工作的通知》（工信部信管〔2023〕105 号）：
  - 在境内从事互联网信息服务的 App 主办者应履行备案；
  - **未履行备案手续的，不得从事 App 互联网信息服务**；
  - App 应在显著位置标明备案编号，并链接备案系统网址；
  - 网络接入服务提供者、分发平台不得为未备案 App 提供接入/分发。
- 《互联网信息服务管理办法》（国务院令第 292 号）：经营性/非经营性互联网信息服务分别许可/备案。
- 《反电信网络诈骗法》：App 备案与真实身份管理。
- 若官网使用境内服务器，还需 ICP 备案；网站上线后 30 日内公安备案；有用户账号的网站通常还需按《网络安全法》第 21 条做等级保护备案/测评。

#### 可能后果

- 被认定“未备案从事互联网信息服务”，责令停止、罚款、阻断访问。
- 应用商店/分发平台拒绝分发；CDN/云服务商停止接入。
- 官网被墙/无法访问，更新链路中断（会连带影响已安装用户）。

#### 整改清单

1. 先确定运营主体（个人/公司）与服务器所在地；向住所地省级通信管理局办理 App 备案。
2. App “关于”页展示备案编号并链接 `beian.miit.gov.cn`。
3. 官网若继续用境外服务器，明确是否面向境内用户；若面向境内，建议迁回境内并办 ICP/公安备案/等保。
4. 隐私政策 URL 作为备案材料的一部分，先上线。
5. 建立备案信息变更/注销流程；保留用户真实身份核验记录（如适用）。

#### 3.2.1 境外云 + 未成年开发者：现实约束与路径

先把两个说法校正一下：

- **不是“法律点名必须用阿里云”**。准确说法是：App 备案必须通过**实际的网络接入服务商**办理；境外 AWS Global 不是境内接入商，不能作为备案通道。AWS 中国区（北京由光环新网运营、宁夏由西云数据运营）属于境内接入商，可以走 ICP/App 备案；阿里云、腾讯云、华为云、UCloud 等也可以。所以“不能转阿里云”不等于“完全不能备案”，但“继续用 AWS Global”确实不能备案。
- **未成年人不能独立作为备案主体**。贵州省通信管理局的公开答复说得很清楚：法规没有写年龄，但备案需要民事行为能力，建议达到完全民事行为能力（18 周岁，或 16 周岁以上以自己劳动收入为主要生活来源）后再申请。部分省份（如吉林）规则是：未满 16 岁用监护人名义备案；16–18 岁需提供收入/工作证明，否则不予备案。各省管局细则不同，但“未成年人自己当主办者”基本走不通。

##### 三条现实路径

| 路径 | 做法 | 优点 | 代价/风险 |
|---|---|---|---|
| **A. 境外 hobby 路线（推荐给现在的你）** | 继续用 AWS Global + GitHub/官网分发；不上国内应用商店；不做 App 备案；不展示任何备案号 | 不需要迁移、不需要监护人做主体、成本最低；适合非商业开源项目 | 法律上仍属“未备案提供互联网信息服务”；国内访问可能被阻断；不能上国内商店；不要声称“已备案” |
| **B. 境内接入路线** | 用 AWS 中国区或任一境内云（不必阿里云）作为实际接入商；由监护人/成年开发者作为主办者；域名做 ICP 备案，再办 App 备案；把 App 面向境内的接口/下载/隐私页迁到境内 | 可以合法上架/长期运营；AWS 中国区可保留 AWS 技术栈 | 需要成年主体（监护人）签字并承担责任；AWS 中国区是独立账号体系，通常要中国主体/企业资料；需要真实迁移一部分后端，不能只挂个反代 |
| **C. 成人/组织代为主办** | 由 ham 社团、公司或成年朋友作为主办者/发布者；你作为开发者；签书面协议，明确责任、账号、收益、退出 | 不需要监护人做主体；可走境内备案 | 主办者承担内容/数据/合规责任；需要信任与协议；应用商店开发者账号也通常要求 18+ |
| **D. 等到 18 岁** | 现在只做开源/境外分发；成年后再备案/上架 | 最干净，不用借主体 | 短期不能上国内商店；如果项目热度上来，会错过窗口 |

##### 不建议的做法

- **买“备案挂靠”、借他人身份证/营业执照、伪造备案号**：这属于虚假备案/冒用身份，风险远大于“没备案”；一旦被查，主体和开发者都会被牵连。
- **境内反代境外 AWS，把它当“已备案”**：ICP 备案要求实际接入资源与备案信息一致；反代只能算灰色变通，数据仍在境外，涉及数据出境与备案真实性，不建议作为长期方案。
- **在 App/官网写“个人开源免备案”**：没有这个豁免；开源、免费、非商业都不免除 App 备案义务（只影响执法优先级）。

##### 我的建议

对“未成年人 + 非商业 + 开源 + 目前只有 GitHub/官网”的项目：

1. **现在走 A**：明确不做国内应用商店、不展示备案号；把隐私政策、FT8 发射门控、Key 轮换这些低成本高风险项先修好。
2. **不要为了备案去借主体/买挂靠**；这会把一个“低风险未备案”变成“虚假备案/身份冒用”。
3. **如果确实要上国内商店**：先和监护人沟通，让监护人作为主办者走 B；或者找可信的 ham 社团/成年发布者走 C；技术上是“境内接入 + 真实主体”，不是“换个云厂商”那么简单。
4. **等 18 岁再正式备案/上架**，是最省心的长期方案；这段时间把项目做成“可迁移”的：域名、隐私政策、接口配置、备案材料都准备好。

> 参考：工信部 105 号文；贵州省通信管理局“个人 ICP 备案年龄限制”答复；腾讯云《吉林管局备案要求》；AWS 中国区 ICP 备案文档；西云数据《APP 备案申请指导流程》。

### 3.3 无线电发射合规：App 本身不是发射台，但它在“帮用户违法”（P0/P1）

#### 事实

- FT8：
  - `Ft8Config.txEnabled` 默认 `false`（`Ft8Models.kt:11`），看起来有“允许发射”开关。
  - 但 `Ft8ViewModel.encodeMessage()`（`Ft8ViewModel.kt:74-118`）和 `playPcm()` 完全不检查 `txEnabled`；`Ft8MainScreen.kt:352-370` 的“编码并播放”按钮也只检查呼号非空。**开关是装饰性的**。
  - 频段表包含 160m/80m/60m/40m/30m/20m/17m/15m/12m/10m/6m/2m（`Ft8Models.kt:22-33`），默认 40m；未询问用户执照类别。
  - FT8 发射页没有“持照/频率/功率”提示。
- SSTV：
  - 发射页有提示（`SstvTxScreen.kt:333`），但“叠加呼号”是可选项（`:300-309`）；不填呼号也能发射。
- 卫星：
  - `SatelliteDetailScreen.kt:168-176` 直接展示“上行频率”（TX），并配合多普勒计算；没有“发射需持照/需协调”的提示。
- APRS：
  - 只读模式、Passcode 用户自持，整改较好；但 `useTls` 配置没有实现，`AprsConnection` 用原始 `Socket`（`:46-52`），Passcode/位置/消息明文传输。

#### 法律依据

《业余无线电台管理办法》（工信部令第 67 号，2024-03-01 施行）：

- 第 3 条：只能用于相互通信、技术研究、自我训练；不得谋取商业利益；未经批准不得广播/通播。
- 第 7 条：设备需型号核准，或自制/改装设备符合国家标准且仅限业余频段。
- 第 8 条：未成年人只能使用 30–3000MHz、功率不大于 25W。
- 第 10 条：15W 以上短波业余电台，向国家无线电管理机构申请。
- 第 30 条：
  - A 类：30–3000MHz，≤25W；
  - B 类：30MHz 以下 <15W，或 30MHz 以上 ≤25W；
  - C 类：30MHz 以下 ≤1000W，或 30MHz 以上 ≤25W。
- 第 35 条：应使用明语或业余无线电公认缩略语、简语，以及公开的技术体制和通信协议。
- 第 36 条：通信日志保留 2 年以上。
- 第 37 条：每次通信建立/结束发呼号，通信中至少每 10 分钟发一次呼号。
- 第 43 条：不得擅自编制/使用呼号；不得向境外组织或个人提供涉及国家安全的境内电波参数资料；不得传播/公布/利用无意接收的信息。
- 第 47–50 条：未经许可设台、擅自使用呼号、干扰业务、向境外提供电波参数资料等，依《无线电管理条例》处罚；构成犯罪的，追究刑事责任。

《无线电管理条例》对应罚则包括责令改正、没收设备、罚款；造成有害干扰可责令暂停发射。情节严重、干扰航空/铁路/军事等，可能触及《刑法》第 288 条“扰乱无线电通讯管理秩序罪”。

#### 典型风险场景

| 场景 | 问题 | 可能后果 |
|---|---|---|
| A 类操作证书用户选择 40m FT8 并“编码并播放” | A 类不能使用 HF；开关又未真正拦截 | 用户被处罚；App 被认定为提供越权发射能力 |
| 用户选择 60m（5.357MHz） | 各国 60m 许可条件不同，App 未按属地/执照过滤 | 境外或境内违规；干扰 |
| B 类用户使用 >15W 短波 | 15W 以上短波需国家无线电管理机构批准 | 用户违规；App 未提示 |
| SSTV 不填呼号直接发射 | 违反第 37 条呼号标识 | 用户被处罚；App 有“帮助规避”之嫌 |
| 未持照用户误触“编码并播放” | 开关失效、无二次确认 | 无照发射；干扰；刑事风险 |
| 用户把 APRS 服务器改成境外 | 位置/呼号/消息出境；第 43 条第 8 项风险 | 行政/刑事风险；数据出境合规问题 |
| 用户使用卫星上行频率 | 未提示卫星操作资格、协调、功率 | 干扰卫星/其他用户；处罚 |

#### 整改清单

1. 首次进入 FT8/SSTV/卫星页时，要求选择“执照类别（A/B/C/无照）”；无照只能接收/本地播放，不显示发射按钮。
2. 按类别锁定频段：A 类禁用 HF；B 类 HF 提示 <15W；C 类 HF 提示 ≤1000W；60m 等按国家/地区配置。
3. 真正实现 `txEnabled` 门控：设置、按钮、ViewModel 三层都检查；默认关闭；每次发射前二次确认。
4. SSTV 强制呼号叠加，或至少默认填入配置呼号，不允许空呼号发射。
5. 卫星上行频率旁增加“发射需持照、需遵守卫星操作规范/协调”的显著提示；默认只显示接收频率。
6. 增加“通信日志保留 2 年”的提醒与导出功能；QSO 日志可一键导出 ADIF。
7. 移除 `useTls` 死配置，或实现 TLS；APRS 默认仅允许 `china.aprs2.net`，切换境外服务器需二次确认与风险提示。
8. 在设置/关于页放《业余无线电台管理办法》摘要与“无照不发射”声明；不要只放一句“后果自负”。

### 3.4 密钥、签名与更新链：这是“技术安全问题”，但会直接变成法律责任（P0）

#### 事实

- **旧方案已删除（2026-10-19）**：`secrets.dat`、`SecretManager.kt`、三碎片、`encryptSecrets` 任务均已移除；地图 SDK 与 Web 服务（天气/逆地理编码）仍全部使用高德，Web Key 构建时写入 `BuildConfig`。
- 本次改造前，`docs/CRYPTO_DESIGN.md:153` 曾明文列出 `amap.api.key` 与 `amap.sdk.key`；这些值仍可能存在于 git 历史，**必须轮换并清理历史**。
- `signing/release.keystore` 与 `signing/github-secrets.txt` 仍在工作区（已被 `.gitignore` 忽略）；`release.ps1` 已改为只读环境变量，但文件本身仍需迁移/删除。
- `app/build.gradle.kts` 已禁止 debug keystore 兜底；release 缺少 `KEYSTORE_*` 时直接失败。
- `Downloader.kt` / `ApkVerifier.kt` 已增加 CDN 白名单、SHA-256、包名、versionCode、签名证书校验；官网 API 已强制官方 CDN + sha256。
- 官网后台仍存在 `FIRST_USER_IS_ADMIN=true`（`website/server/config.mjs:203`）、无 MFA、无管理员邮箱白名单（默认空）的默认配置；这是下一节要处理的重点。

#### 法律/合同依据

- 高德开放平台服务协议：开发者对 Key 的保管、使用范围、真实信息负责；Key 泄露/转用可能构成违约，导致服务停用、赔偿。
- 《网络安全法》第 21、42 条：网络运营者应采取技术措施保障网络安全、防止个人信息泄露。
- 《个人信息保护法》第 51 条：加密、访问控制、备份等安全措施。
- 《民法典》侵权责任编：因过错造成他人损失的赔偿责任。
- 若被用于分发恶意 APK，可能触及《刑法》第 285/286 条（非法控制/破坏计算机信息系统），并引发用户集体索赔。

#### 可能后果

- 高德 Key 被滥用：配额耗尽、产生费用、服务被停；若被用于违法请求，开发者可能被调查。
- debug 签名被伪造：攻击者可发布“同名同签名”的恶意更新，用户无感知安装；开发者承担信任与赔偿责任。
- 官网后台被接管：推送恶意 APK，形成供应链攻击；这是最严重的声誉/法律事件。
- 更新包被替换/劫持：用户设备被入侵、数据泄露。

#### 整改清单

1. **立即轮换**高德 Web 服务 Key 与 Android SDK Key；用 `git filter-repo`/BFG 清理历史；通知所有 fork/协作者。
2. 不再把 Key 放进仓库；地图 SDK + Web 服务（天气/逆地理编码）仍使用高德；SDK Key 按包名 + 签名 SHA-1 限制，Web Key 无法绑定 Android 包名，只能靠配额/监控，并接受“客户端 Key 可被提取”的现实。
3. 已删除旧的 `secrets.dat`/三碎片方案；`docs/CRYPTO_DESIGN.md` 已改为“客户端不放秘密”。
4. release 构建在缺少 release keystore 时**直接失败**，不再回退 debug。
5. 更新包校验：HTTPS + 固定域名白名单 + SHA-256 + APK 签名证书指纹；校验失败拒绝安装。
6. 官网后台 `downloadUrl` 只允许 `apk.hamkit.click` / 官方 GitHub Release 域名；`sha256` 必填并校验。
7. 管理员：关闭 `FIRST_USER_IS_ADMIN`（初始化后）、配置 `BOOTSTRAP_ADMINS` 与 `ALLOWED_EMAIL_DOMAINS`、启用 MFA、限制管理后台 IP、审计告警。
8. 密钥管理：release keystore 与密码分离存放（HSM/Secret Manager），不要把密码写在 keystore 同目录的 txt 里；AWS 使用最小权限 IAM，不用 root。
9. 建立安全事件预案：Key 泄露、APK 被替换、后台被入侵时的下架/公告/取证/通知流程。

### 3.5 数据出境：官网和云备份是两条独立通道（P1）

#### 事实

- 官网/对象存储在境外：文档写明 S3 `ap-east-2`（台北）、CloudFront、官网服务器境外 IP。
- 官网保存用户邮箱、显示名、头像、IP（审计日志始终记录 IP；统计可选）、会话。
- App 默认 `allowBackup=true`，云备份可能把呼号、Passcode、QSO 日志、APRS 消息/位置、录音/图片同步到 Google/厂商云。
- APRS 默认连 `china.aprs2.net`，但用户可以改成任意境外服务器；`AprsHttpUploader` 还残留 `api.aprs.fi`（芬兰）接口，虽然当前未见调用。
- App 更新请求会向 `hamkit.click` 发送 IP/UA。

#### 法律依据

- 《个人信息保护法》第 38 条：向境外提供个人信息，应满足安全评估、标准合同（并备案）、认证或其他条件之一；第 39 条：单独同意 + 告知境外接收方信息。
- 《数据安全法》第 27、29、36 条：数据安全管理制度、风险监测、跨境提供管理。
- 若涉及欧盟/英国用户：GDPR/UK GDPR 第 6、13、44 条等；无隐私政策、无合法基础、无跨境机制，罚款上限 2000 万欧元或全球营业额 4%。
- 若涉及加州用户：CCPA/CPRA 的收集告知义务（无“出售”情形则压力较小）。

#### 可能后果

- 责令整改、警告、罚款；情节严重的暂停业务。
- 用户投诉/集体诉讼；海外监管调查。
- 与境外云厂商/IdP 的数据处理协议缺失，责任边界不清。

#### 整改清单

1. 画一张数据地图：字段、目的、存储地、接收方、保留期、跨境路径。
2. 优先本地化：官网迁回境内，或至少把用户账号数据放境内；APRS 默认境内服务器。
3. 若必须出境：做安全评估/标准合同备案/认证；签 DPA；做传输影响评估；隐私政策单列“跨境”章节并单独同意。
4. 关闭不必要的云备份，或在备份规则中排除敏感数据；Passcode 不进入备份。
5. 删除 `AprsHttpUploader` 等未使用的境外接口，减少攻击面与合规解释成本。

### 3.6 开源许可与第三方数据：不是“写个 MIT 就完了”（P1）

#### 事实

- 项目整体 MIT，但 APK 内包含大量 Apache-2.0 / ISC / MIT / 可能 GPL 的代码：

- Apache-2.0：保留版权/专利/署名声明，提供许可证副本，附 NOTICE（如有）。

- CelesTrak/SatNOGS/AMSAT 的使用条款/数据库权利。

#### 可能后果

- 著作权人发函/诉讼，要求停止分发、公开源码、赔偿；平台投诉下架。

#### 整改清单

### 3.7 地图与测绘：低概率、高处罚（P2）

#### 事实

- 使用高德 3D 地图 SDK 展示定位、APRS 站点、卫星星下点/轨迹。
- APRS 允许用户上传/显示位置标注；卫星地图含地面轨迹、覆盖圆。
- 未见审图号、测绘资质说明；高德底图自带审图号/Logo 时，叠加层是否需单独审核存在解释空间。
- 服务器/数据：高德底图在境内；TLE 镜像在境外（非地图数据）。

#### 法律依据

- 《地图管理条例》：
  - 第 33 条：互联网地图服务单位提供地理位置定位、地理信息上传标注、地图数据库开发等，应取得测绘资质；
  - 第 34 条：地图数据服务器应设在境内；
  - 第 35 条：收集/使用用户个人信息应明示并取得同意；
  - 第 38 条：使用经审核批准的地图，对新增内容核查校对并备案；
  - 第 54 条：使用未经审核地图/未核查新增内容，最高 20 万元罚款，情节严重责令停业/吊销资质。
- 《测绘法》第 27、51 条：测绘资质与罚则。
- 若发布 standalone 地图图片（如卫星轨迹图）到官网/社交媒体，可能触发地图审核/审图号要求。

#### 风险判断

- 多数嵌入高德 SDK 的 App 由高德承担底图资质，App 本身不被单独要求测绘资质；但 HamKit 的“用户位置标注 + 地图展示”更接近“地理信息上传标注”，存在被认定为互联网地图服务的解释空间。
- 执法概率低，但一旦被认定，处罚上限不低，且可能要求下线地图功能。

#### 整改清单

1. 保留高德 Logo/审图号，不遮挡、不裁剪。
2. 不发布 standalone 地图图片；如发布，先做地图审核。
3. 请地图合规律师/高德商务确认“APRS 站点标注 + 卫星轨迹叠加”是否需要额外资质/备案。
4. 地图数据服务器保持境内；不要把地图数据同步到境外。
5. 在隐私政策中说明地图 SDK 的数据处理。

### 3.8 免责条款与产品责任：一句“后果自负”保护不了你（P2）

#### 事实

- `about_disclaimer`：“本应用提供的卫星过境预测、天气、定位等信息仅供参考……使用本应用产生的一切后果由用户自行承担。”
- FT8 发射页没有安全提示；SSTV 有提示但不够；卫星上行频率无提示。
- 目前没有天线旋转器控制，但 `requirements/REQ-0003` 规划了旋转器控制；一旦实现，硬件控制可能造成财产/人身损害。

#### 法律依据

- 《民法典》第 497 条：格式条款不合理地免除/减轻提供方责任、加重对方责任、限制对方主要权利的，无效；造成人身损害、因故意/重大过失造成财产损失的免责条款无效。
- 《民法典》第 1165 条：过错侵权责任。
- 《消费者权益保护法》第 18 条（安全保障）、第 26 条（格式条款）；若未来收费，适用更强。
- 《产品质量法》：缺陷产品造成人身/财产损害的责任；软件是否属“产品”有争议，但并非绝对排除。

#### 可能后果

- 免责条款被认定无效；用户因预测错误/发射干扰/设备损坏索赔。
- 若未来做旋转器控制，硬件误动作可能造成天线/设备损坏或人身伤害，责任更重。

#### 整改清单

1. 把“免责声明”改成“风险提示 + 责任限制”，避免“一切后果”这种绝对表述；对人身损害/故意/重大过失不得免除。
2. FT8/SSTV/卫星页增加“无照不发射、频率/功率合规、勿干扰”的显著提示与二次确认。
3. 若做旋转器控制：加限位、急停、超时、角度校验、硬件隔离与安全说明书；购买产品责任保险。
4. 保留预测算法版本、TLE 时间戳、误差说明，便于举证已尽合理注意。

### 3.9 网站个人信息与后台安全：小站也有 PIPL 义务（P1）

#### 事实

- 官网有 OIDC 登录、用户中心、管理后台，保存邮箱、显示名、头像、角色、登录时间、IP、审计日志。
- 没有隐私政策、用户协议、Cookie 说明、账号注销/数据导出入口。
- `FIRST_USER_IS_ADMIN=true`；`ALLOWED_EMAIL_DOMAINS` 默认空；无 MFA；管理后台可改 `downloadUrl`。
- 数据以 JSON 文件存磁盘；未见加密、备份、访问审计（有审计日志，但无告警）。
- 若服务器在境内，需 ICP/公安备案/等保；若境外，PIPL 仍适用。

#### 法律依据

- 《个人信息保护法》第 13、17、38、39、47、51 条。
- 《网络安全法》第 21 条（等级保护）、第 24 条（实名制，若提供信息发布）、第 42 条（数据安全）。
- 《计算机信息网络国际联网安全保护管理办法》（公安备案）。
- 《互联网信息服务管理规定》/App 备案。

#### 可能后果

- 用户投诉、监管检查、罚款；账号数据泄露。
- 管理员账号被接管 → 推送恶意 APK → 供应链事件，可能引发刑事责任与集体索赔。

#### 整改清单

1. 上线隐私政策/用户协议/Cookie 说明；说明邮箱、IP、日志的用途与保留期。
2. 提供账号注销、数据导出、更正入口；删除后真正清除关联数据（审计日志可依法保留并说明）。
3. 关闭 `FIRST_USER_IS_ADMIN`；配置 `BOOTSTRAP_ADMINS` / `ALLOWED_EMAIL_DOMAINS`；启用 MFA；限制后台 IP。
4. 管理后台操作二次确认（尤其是发布 APK/改下载地址）；关键操作邮件/IM 告警。
5. 数据加密、备份、最小权限、日志留存；制定泄露通知流程。
6. 若境内：办 ICP/公安备案/等保；若境外：做跨境评估与标准合同。

### 3.10 商店与分发政策：不是法律，但会决定能不能发（P2/P1）

| 项 | 现状 | 风险 |
|---|---|---|
| `REQUEST_INSTALL_PACKAGES` | 应用内下载 APK 并安装 | Google Play 受限权限，非“核心功能”通常拒绝；国内商店也敏感 |
| `USE_EXACT_ALARM` | 过境提醒 | Play 仅允许闹钟/日历类核心功能；可能拒审 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 提醒保活 | Play 受限；需核心功能论证 |
| `hiddenapibypass` | 绕过 Android 隐藏 API | Play“Device and Network Abuse/Deceptive Behavior”风险；系统升级易崩 |
| `com.example.hamkit` | 包名 | Play/国内商店通常不接受；品牌与唯一性不足 |
| Amap SDK | 专有依赖 | F-Droid 不接受非自由依赖；无法满足“全自由软件” |
| 自更新 | 官网 APK | Play 禁止绕过商店自更新；国内商店也有审核要求 |

**建议：**

- 如果目标是 Google Play：移除自更新，改用 Play In-App Updates；删除 `REQUEST_INSTALL_PACKAGES`、`USE_EXACT_ALARM`、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 或做核心功能论证；移除 `hiddenapibypass`；改包名；补 Data Safety/隐私政策。
- 如果目标是国内商店：先 App 备案、软著、隐私政策、权限说明、安全检测；自更新通常不被允许。
- 如果目标是 F-Droid：做无 Amap/无专有 SDK 的 flavor；确保所有依赖自由许可、可复现构建。
- 如果只做官网/GitHub  sideload：上述商店政策不直接适用，但仍受 App 备案、网络安全、个人信息保护约束；自更新必须做签名/哈希校验。

### 3.11 高德“5 万元/年商用授权”到底怎么回事（补充）

这张图**数字有来源，但结论被说绝对了**。它把“企业商用授权”说成了“所有公开 App 上架就自动收 5 万”，这与高德现行协议和定价页并不完全一致。

#### 协议实际怎么写

高德《开放平台服务协议》（2025-12-03 版）的关键区别是“自然人”和“法人/非法人组织”：

- **自然人**（第 3.1 条）：只有以“**个人研究学习目的**”使用，个人认证开发者才享有每月一定额度的免费基础服务配额；以**其他目的**使用的，需要创建工单办理付费许可。
- **法人/非法人组织**（第 3.2 条）：需要事先购买“技术服务许可”。“商业目的”包括向第三方或公众用户收费、参与投标、用于内部管理系统/后台管理系统，以及**任何直接或间接获取收益或利益**的用途；为第三方开发系统时，开发方和运营方都要买。
- **超量**（第 3.7 条）：超出配额/并发限制，高德可以拒绝请求、限流，并要求按官网价格支付超限费用。

也就是说：

- 对**个人**，触发点不是协议里逐字写的“商用”，而是“**超出个人研究学习目的**”。一个公开上架、有真实用户、持续运营的 App，是否仍算“个人研究学习”，解释权在高德，存在灰区。
- 对**企业**，触发点确实是“商业目的”，而且定义很宽（连内部管理系统都算）。
- “长期或大量调用”本身不是“商用”的定义，而是**配额/超限**问题：可能被限流、要求买流量包或升级许可。

#### 定价页实际怎么写

高德 `lbs.amap.com/upgrade` 当前展示的是**按量价格 + 月配额**，例如：

- 基础 LBS 服务 30 元/万次；
- 基础地图定位 3 元/万次；
- 天气查询 30 元/万次；
- 个人认证开发者（非商业目的）月配额：基础 LBS 15 万次、基础地图定位 150 万次、搜索 5,000 次、天气 5,000 次；
- 企业认证开发者（技术服务许可）月配额：基础 LBS 900 万次、基础地图定位 9,000 万次等。

官方页面**没有**写“所有企业商用统一 5 万元/年”。5 万元/年更像是企业“技术服务许可”的**常见起步报价/基础档**，具体以商务报价和许可协议为准；把它称为“行业统一定价”是不准确的——百度、腾讯、高德的套餐、配额、折扣、谈判空间都不同。

#### 逐条对照

| 图中说法 | 实际情况 | 对 HamKit 的含义 |
|---|---|---|
| “5 万元/年固定年费” | 商用许可通常是年度授权费，但价格按档位/配额/谈判定；官方页面当前以按量价格 + 月配额为主 | 不要把它当成“上架就自动扣 5 万”；它是**商业授权成本**，不是罚款 |
| “不是按调用量计费” | 商用许可含配额，超出配额仍要按量付费/买流量包；个人免费额度也是按月配额 | 小规模使用通常先看免费配额；Key 泄露导致刷量才是真风险 |
| “高德/百度/腾讯行业统一定价 5 万” | 没有“行业统一定价”；各家套餐不同，5 万只是常见起步报价 | 不要拿这张图当报价依据；直接问高德商务/工单 |
| “面向公众上线/应用商店上架 = 商用” | 协议没有这句原话；对个人是“超出个人研究学习目的”，对企业是“商业目的”。公开上架是**重要证据/风险因素**，但不是自动等同 | 个人免费开源 App 处于灰区；小范围 GitHub 分发风险较低，公开上架/推广会被更认真地审视 |
| “长期或大量调用 = 商用” | 这是配额/超限问题，可能限流、收费，不等于“商用”定义 | 控制调用量、监控配额；不要用个人 Key 跑高流量服务 |
| “开发测试免费额度是另一回事” | 对：免费额度限定“个人研究学习/非商业目的”，生产/商用要另算 | 不要用“开发测试”名义长期跑公开服务 |

#### 5 万元是“授权费”，不是“罚款”

- 不买授权的主要后果是**合同层面**：高德可要求限期购买、暂停/终止服务、按超限价格收费；不是行政机关直接开 5 万罚单。
- 但如果继续使用被终止的服务、或泄露 Key 导致他人刷量，可能构成违约/侵权，产生额外赔偿；这时才可能进入诉讼。
- 对个人开源项目，现实中最常见的结果是**地图/天气/逆地理编码突然不可用**，而不是被起诉。

#### 对 HamKit 的现实建议

HamKit 是免费、无广告、个人开源、GitHub/官网分发，当前用量大概率在个人免费配额内。可按以下决策树处理：

1. **保持 hobby、不商业化、不公开大规模推广**：用个人认证开发者账号，控制在月配额内；给高德提工单，书面确认“免费开源、无广告、无收费的公开 App 是否属于非商业目的”。拿到书面答复再放心。
2. **要上应用商店/公开推广**：先问高德商务该场景是否需要技术服务许可；若报价 5 万/年，对免费项目通常不划算，考虑：
   - 去掉地图卡片，只保留网格/坐标文本；
   - 换成 osmdroid/MapLibre 等开源底图（但中国地图合规/审图号是另一套问题）；
   - 用离线网格图/简化示意图，不接在线地图。
3. **要商业化（广告/捐赠/付费/公司运营）**：把 5 万/年（或实际报价）计入成本，先买许可再上线。
4. **无论哪条路**：先处理 Key 泄露（见 3.4）。Key 被刷量会直接把你从“个人免费”推到“超量/商用审查”。

**一句话：这张图提醒的方向是对的——高德不是“随便免费用”；但它把“企业商用授权”说成了“所有公开 App 上架就收 5 万”，把报价说成了统一定价，把合同后果说成了罚款。对 HamKit，先按个人非商业用、控制配额、拿书面确认；要上架/商业化再谈授权或换方案。**

## 六、总体判断

HamKit 的功能完成度不低，APRS Passcode 整改、SSTV 提示、OIDC 安全都说明团队有合规意识。但目前的风险结构是：

> **“无线电合规”有提示但缺硬门控；“个人信息合规”基本空白；“互联网信息服务备案”缺失；“密钥/更新链”是明显短板；“开源/数据许可”是长期负债。**

如果只是个人学习/小范围 ham 社群 sideload，行政执法的概率相对低；但只要出现以下任一情形，风险会迅速放大：

- 上架应用商店 / 国内分发；
- 面向未成年人或普通公众推广；
- 用户因无照发射被查处，追溯 App 的“发射开关”；
- 高德 Key 被滥用/产生费用；
- 官网后台被接管并推送恶意 APK；
- 用户位置/Passcode/QSO 日志泄露；
- 著作权人/数据权利人投诉。

建议先把 P0 的五件事做完，再考虑上架/商业化。**在没有隐私政策、App 备案、发射门控和签名/更新校验之前，不建议面向公众大规模分发。**
