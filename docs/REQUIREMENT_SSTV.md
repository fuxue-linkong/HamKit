## 三、SSTV 协议技术调研

### 3.1 信号形态

SSTV 是**模拟调频（FM）图像传输**：亮度/色度被线性映射为音频频率，逐像素顺序发送。

| 参数 | 值 |
|---|---|
| 音频带宽 | **1500 Hz（黑）～ 2300 Hz（白）**，占用约 800 Hz |
| 调制方式 | 频率调制（与 FT8 的 MFSK 不同，是**连续模拟**而非离散音调） |
| 单帧时长 | 36 s（Robot 36）～ 268 s（Scottie DX） |
| 分辨率 | 320×240 / 320×256 / 640×496 |
| 关键同步信号 | **1200 Hz 同步脉冲**（低于黑电平，可被稳定检测） |
| 模式标识 | 音频开头的 **VIS 头**（数字编码的模式号） |

**与 FT8 的本质差异**：FT8 是「离散音调 + 固定时隙」，SSTV 是「连续频率 + 严格行节拍」。因此 SSTV 解码的核心不是频域搜索，而是**高精度瞬时频率估计 + 时间轴对齐**。

### 3.2 VIS 头规范

每帧图像前有一个数字头，用于标识模式。**发射端完整时序**（逐项核对 slowrx `vis.rs` 的合成函数 `synth_vis_with_offset` 与 `vis.c` 常量）：

| # | 阶段 | 频率 | 时长 | 作用 |
|---|---|---|---|---|
| 1 | Leader 1 | 1900 Hz | 300 ms | 建立 AGC / 时钟 |
| 2 | Break | 1200 Hz | 10 ms | 分隔标记 |
| 3 | Leader 2 | 1900 Hz | 300 ms | 建立 AGC / 时钟 |
| 4 | **起始位** | 1200 Hz | 30 ms | 位串开始 |
| 5 | 数据位 ×7 | **1100 Hz = `1`，1300 Hz = `0`** | 各 30 ms | **LSB 先传** |
| 6 | 偶校验位 ×1 | 同上 | 30 ms | 使 8 位中 `1` 的个数为偶数 |
| 7 | 停止位 | 1200 Hz | 30 ms | 帧结束 |

> ⚠️ **电平极性易错**：`1100 Hz = 1`、`1300 Hz = 0`。若写反，所有 VIS 码都会解成另一个合法码或查表失败（slowrx 常量：`BIT_ONE_OFFSET = −800` → 1100 Hz；`BIT_ZERO_OFFSET = −600` → 1300 Hz）。

- 有效数据位共 8 位（7 数据 + 1 奇偶），故 VIS 码取值 `0x00`–`0x7F`。
- 整个 VIS 头 **910 ms**。
- 校验失败或码值未定义时，应回到 IDLE 重新侦听（**不可当作致命错误**；slowrx 的语义是 `while (Mode == 0)` 重侦听）。
- **特例**：Robot 12 B/W（`0x06`）使用**奇校验**（slowrx `vis.c:116` 对该码翻转奇偶位）。实现时不要写死偶校验。

**检测端的等效简化**（slowrx 的做法，值得直接借鉴）：

检测只使用 VIS 头**最后 450 ms** 的滑窗，即 `[Leader 2 尾部 150 ms][起始位 30 ms][7 数据位][校验位][停止位 30 ms]`。因此：

- 第一个 Leader、Break 与 Leader 2 的前 150 ms **不参与判定**（滑窗尚未覆盖），无需专门检测 1900→1200 的跳变。
- 滑窗内两个 1200 Hz 检查点（索引 15 与 42）实际分别是**起始位**与**停止位**——slowrx 常量名 `BREAK_HZ_OFFSET` 是历史命名，不要被误导。
- 这使检测退化为「在 45 个 10 ms 频率采样上做模式匹配」，比边沿触发状态机更抗噪。

### 3.4 三个模式族的布局差异

> 本节结论逐项核对自 slowrx 的 `mode_pd.rs` / `mode_robot.rs` 与 `video.c` 的通道时序公式
> `ChanStart[n+1] = ChanStart[n] + ChanLen[n] + SeptrTime`，并用「行周期 = 各通道时长之和」反向验证通过（见下方推导）。

| 族 | 通道顺序（一个无线行内） | 色度处理 | 难点 |
|---|---|---|---|
| **PD 族** | `Sync + Porch + Y₁(640) + Cr(640) + Cb(640) + Y₂(640)` | **水平全分辨率、垂直 2:1 共享**：Cr/Cb 各 640 样本，供**相邻两个图像行共用** | 必须成对处理两行；色度行配对错位 → 图像发绿/偏色 |
| **Robot 24/36** | `Sync + Porch + Y(320) + 分隔 + C(320)`，其中 **Y 每像素占 2× 像素时间** | **每行只发一个色度分量**（偶行 Cr / 奇行 Cb），并**复制到下一图像行** | 行奇偶决定发 Cr 还是 Cb；奇偶判错 → 色彩错位 |
| **Robot 72** | `Sync + Porch + Y(320) + 分隔 + U(320) + 分隔 + V(320)` | 每行完整 U/V（三通道等宽） | 与 24/36 同族不同构，需分支处理 |
| **Martin** | `Sync + Porch + G(320) + 分隔 + B(320) + 分隔 + R(320)` | 全采样 RGB，无子采样 | 三通道顺序为 **G→B→R**（非 RGB） |
| **Scottie** | `[sep] + G + [sep] + B + [Sync] + [porch] + R`（**同步在行中**，行首本身是一个分隔脉冲） | 全采样 RGB | 行首位于同步脉冲**之前** `2·sep + 2·chanLen`，必须由实测同步位置反推；编码时同步脉冲插在 B 与 R 之间 |

**PD 模式时间轴推导**（以 PD-120 反向验证通道公式，`chan_len = 640 × 190 µs = 121.6 ms`）：
```
Y₁:   640 px × 190 µs = 121.60 ms
Cr:   640 px × 190 µs = 121.60 ms     ← 色度也是全宽 640，不是 320
Cb:   640 px × 190 µs = 121.60 ms
Y₂:   640 px × 190 µs = 121.60 ms
sync 20 ms + porch 2.08 ms = 22.08 ms
────────────────────────────────────
合计 = 508.48 ms  ✓ 与 modespec 的行周期完全一致
```
248 个无线行（= 496 图像行） × 508.48 ms = **126.1 s** ✓

**Robot 36 时间轴推导**（验证「Y 占 2× 像素时间」这一非常规设定）：
```
Y:    320 px × (2 × 137.5 µs) = 88.00 ms
分隔:                            6.00 ms
C:    320 px × 137.5 µs       = 44.00 ms
sync 9 ms + porch 3 ms        = 12.00 ms
────────────────────────────────────
合计 = 150.00 ms  ✓ 与 modespec 的行周期完全一致
```
> 若按「Y 与色度同为 1× 像素时间」实现，每行只有 106 ms，与 150 ms 相差 44 ms —— 图像会整体挤压缩放。这是该族最容易踩的坑。

**Martin 1 时间轴推导**（三通道等宽 + 3 个分隔）：
```
G/B/R: 3 × 320 px × 457.6 µs = 439.296 ms
分隔:   3 × 0.572 ms         =   1.716 ms
sync 4.862 + porch 0.572     =   5.434 ms
────────────────────────────────────
合计 = 446.446 ms  ✓ 与 modespec 的行周期完全一致
```

### 3.5 为什么 PD-120 是 ISS 首选

- ARISS 现行活动**统一使用 PD120**（[ARISS News Release 25-52](https://ariss-usa.org/ariss-sstv-event-scheduled-for-this-week-3/)，145.800 MHz）。
- PD120 分辨率 640×496，是常用模式中画质最高的。
- 代价：单帧 126 s，要求 ISS 过境窗口（通常 5–10 min）能覆盖一到两张图 —— 与 HamKit 的过境预测能力天然契合。

## 四、解码链路设计

### 4.1 链路总览

```
① 采集      AudioRecord 48 kHz mono → 环形缓冲
              │
              ├──────────────────────────────┐
              ↓（低频支路）                   ↓（高频支路）
②A VIS 检测  10 ms hop / 20 ms Hann / FFT    ②B 像素解调  逐样本正交鉴频
   峰值 + 亚 bin 插值 → 45 项频率历史            → f(t) 频率流（48 k samples/s）
              ↓                                ↓
③  模式识别  滑窗模板匹配 + 偶校验 + 失谐补偿     │
   锁定模式 SstvMode, hedr_shift                │
              └──────────────┬─────────────────┘
                             ↓
④ 行同步    检测 1200 Hz 脉冲 → 行节拍器 + slant 最小二乘校正
                             ↓
⑤ 像素采样  按模式时序在像素时间窗内取频率均值 → 亮度/色度（用 hedr_shift 校正黑白基准）
                             ↓
⑥ 成像      YCrCb/YUV → RGB → Bitmap 逐行增量刷新 → PNG 落盘
```

### 4.2 采样率论证（**关键工程结论**）

| 模式 | 像素时长 | @8 kHz | @16 kHz | **@48 kHz** |
|---|---|---|---|---|
| PD-120 | 190 µs | 1.52 样本 ❌ | 3.04 样本 ⚠️ | **9.12 样本 ✅** |
| Robot 36 | 137.5 µs | 1.10 样本 ❌ | 2.20 样本 ❌ | **6.60 样本 ✅** |
| Scottie 1 | 432 µs | 3.46 样本 ⚠️ | 6.91 样本 ✅ | 20.7 样本 ✅ |
| Martin 1 | 457.6 µs | 3.66 样本 ⚠️ | 7.32 样本 ✅ | 22.0 样本 ✅ |

**结论**：SSTV 带宽虽仅 800 Hz（8 kHz 采样足以满足 Nyquist），但**时间分辨率**要求远高于频率分辨率。FT8 用的 12 kHz 采样在 PD-120 下每像素仅 2.3 个样本，无法在像素中点稳定取值。

→ **必须按 48000 Hz 采集与处理**（首选），回退 44100 Hz。不需要重采样（与 FT8 相反）。

### 4.3 频率估计：**两级处理**架构

**关键设计结论**：VIS 检测（位宽 30 ms）与像素解调（像素宽 137–457 µs）对时间分辨率的要求相差**两个数量级**，**必须用两种不同算法**，不可共用一套参数。

| 用途 | 需要的时间分辨率 | 需要的频率精度 | 适用算法 |
|---|---|---|---|
| **VIS 检测** | 30 ms（位宽） | ±25 Hz | 短时 FFT 峰值跟踪 + 亚 bin 插值 |
| **像素解调** | 137–457 µs（像素宽） | ±5 Hz | 逐样本瞬时频率（相位差分） |

> 若用 FFT 峰值法解像素：PD-120 像素仅 190 µs，FFT 窗必须 ≤ 190 µs，在 48 kHz 下仅 9 个样本 → 频率分辨率 ≈ 5.3 kHz，完全不可用。反之，用逐样本鉴频去检测 30 ms 长的 VIS 位则噪声敏感、浪费算力。

**VIS 检测（低频更新率）**——推荐直接照搬 slowrx 参数（它是经充分验证的）：
- 步长（hop）**10 ms**、窗长 **20 ms**、Hann 窗
- 20 ms 窗 @48 kHz = 960 样本，**零填充到 2048 点 FFT** → 频率分辨率 ≈ 23 Hz/bin
  （slowrx 在 44.1 kHz 下用 2048 点；slowrx.rs 在 11.025 kHz 下用 512 点——三者分辨率等价）
- 峰值搜索范围 **500–3300 Hz**，用**高斯-对数插值**细化到亚 bin 精度：
  ```
  bin = k_max + ln(P[k+1]/P[k−1]) / (2·ln(P[k]² / (P[k+1]·P[k−1])))
  ```
- 维护 **45 项**（450 ms）频率环形历史，供 §4.4 的模式匹配使用
- 边界或不单调的峰值 → 沿用上一 hop 的值（避免野值污染历史）

**像素解调（高时间分辨率）**——三方案对比：

| 方案 | 原理 | 每样本开销 | 精度 | 实现复杂度 | 评价 |
|---|---|---|---|---|---|
| **A. 分块 FFT-Hilbert** | 逐块 FFT → 负频置零 → IFFT 得解析信号 → `atan2` 相位差分 | ~200 flops（块 1024 / hop 256） | 高 | 中（需自研 FFT） | 精度最好，但块边界需重叠，FFT 代码量约 150 行 |
| **B. 复数混频正交鉴频** ⭐ | 与 1900 Hz 本振混频 → 低通（I/Q）→ `atan2` 相位差分 | ~60 flops | 高 | **低** | **FM 鉴频的标准做法**（数字下变频 + 鉴频器），等效于 A 但计算量小 3 倍 |
| **C. FIR Hilbert 变换器** | 61 抽头 FIR 求正交分量 → 相位差分 | ~70 flops | 中高 | 低 | 系数可预生成常量表 |
| D. 过零检测 | 统计过零点间隔 | 极低 | 低 ❌ | 极低 | 噪声下不可用，**排除** |

**推荐像素解调用方案 B**：
```
I(t) = LPF( x(t) · cos(2π·f₀·t) )      f₀ = 1900 Hz（带中心）
Q(t) = LPF( x(t) · −sin(2π·f₀·t) )
φ(t) = atan2(Q, I)
f(t) = f₀ + unwrap(φ(t) − φ(t−1)) · fs / 2π
```
- **低通必须用 8 阶 Butterworth、截止 1200 Hz**（而非 2/4 阶 + 600 Hz）—— 这是实现阶段实测
  得出的硬性要求，源于一对相互冲突的约束（详见 §11.2）：截止越宽则水平过渡带越窄（图像越锐利），
  但 2f₀≈3800 Hz 的和频镜像也越强；只有提高阶数才能两者兼得。
- **必须做相位解缠（unwrap）**：`Δφ` 折叠到 `(−π, π]`，否则频率会出现 ±fs 的跳变。
- **相位差应取「间隔 span 个样本的后向差分」而非相邻样本差分**：相邻样本差分只用到 2 个相位值，
  噪声标准差约 200 Hz 量级；间隔 span 的差分使噪声按 `1/span` 线性下降，而时间分辨率降为 `2·span`
  个样本（对 PD-120 取 span=4 恰好落在一个像素内，见 `SstvDemodulator.recommendPhaseSpan`）。
- 对 PD120 而言，`f(t)` 精度要求见 §4.8。

> **参考实现的采样率参考**：slowrx.rs 以 **11.025 kHz** 为工作采样率（在 PD-120 下每像素仅 ~2.1 样本，靠样本间插值取值）即可获得可用图像。本方案采用 48 kHz（每像素 ~9 样本），精度余量更大、且省去重采样环节。

### 4.4 VIS 检测：滑窗模式匹配（推荐）与失谐补偿

**推荐方案：滑窗模式匹配**（slowrx 的做法，已在实践中充分验证）

每产生一个新的 10 ms 频率估计（hop），就在 45 项历史窗口上尝试匹配 VIS 模板：

```
模板索引（hop，10 ms 一步）：   0   3   6   9  12 | 15 | 18+3k (k=0..6) | 39 | 42
对应信号段：                  ← Leader 2（150 ms）→| 起始位|  7 个数据位   |校验|停止
```

- **9 种对齐尝试**：`i ∈ {0,1,2}`（3 个相位偏移）× `j ∈ {0,1,2}`（3 个 leader 候选），全部尝试后取第一个**已知且校验通过**的码（不要遇到未知码就提前退出——已知码可能出现在后续对齐上）。
- **容差为相对值 ±25 Hz**，相对基准是**实测 leader 频率**，不是标称 1900 Hz（见下）。
- 未知但校验通过的码 → 仍上报（便于排障 / 未来扩展），但解码器回到 IDLE。
- 每次检测成功后，检测器必须**重建**（历史/计数清零），不可复用。

**必做：失谐补偿（`hedr_shift`）**

```
hedr_shift = 实测 leader 频率 − 1900 Hz
```

电台与接收机之间总有几 Hz ~ 上百 Hz 的频率偏差（失谐、多普勒、声学路径）。因此：

- 所有参考频率判定都应以 `实测 leader + 偏移常数` 为基准（如 `起始位目标 = leader − 700`）。
- `hedr_shift` 还要**传给像素解调级**，用于校正 1500/2300 Hz 黑白基准，否则整幅图像会偏亮或偏暗。
- 这是「多普勒下能否解出 ISS SSTV」的关键一环。

**备选（更简单但更脆）：边沿状态机**

```
IDLE ──1900 Hz 持续 ≥250 ms──▶ LEADER
LEADER ──转 1200 Hz，持续 5–50 ms──▶ BITS（按 30 ms 节拍采 8 位）
BITS ──偶校验通过──▶ 锁定模式
     ──失败/未知──▶ IDLE（计数一次失败，不中断音频流）
```
- 优点：代码短。缺点：对噪声与幅度起伏更敏感，且须处理「两个 leader 之间的 10 ms break」与「起始位」都是 1200 Hz 的歧义。
- 若采用，务必以**频率相对实测 leader 偏移**来判定，并取「每位中点 ±5 ms 窗内均值」而非单点采样。

**共同要求**：
- **不要用绝对频率阈值**（`f > 1800` 判 1900 Hz）。信号幅度受电台音量、AGC、麦克风距离影响极大，须先做幅度估计/归一化。
- 提供**手动模式锁定**：用户跳过 VIS 直接按指定模式解码。VIS 在弱信号下失败率不低，这是必需的兜底（见 §9 R2）。

### 4.5 行同步与 slant 校正

**同步脉冲检测**：在频率流中寻找「落在 1200 Hz、经 `hedr_shift` 校正后偏差 ≤ 50 Hz、持续时长 ≥ 同步时长 × 0.6」的连续段。

**slant（斜率）校正** —— 不做会导致图像明显斜切：
1. 记录每行同步脉冲的**实际起始样本位置** `p[n]`。
2. 对 `(n, p[n])` 做**最小二乘线性回归** → 实际行周期 `T_real`（对比模式标称 `T_nominal`）。
3. 偏差来源：电台/手机时钟不同源 + 多普勒 + 声卡漂移。`T_real/T_nominal` 常在 0.99–1.01 之间。
4. 用 `T_real` 重算每行的像素采样位置（等价于对时间轴重采样）。
5. 可选：一阶 PLL 跟踪，平滑单行同步检测的抖动。

**行起始偏移**：`SyncPosition::LineStart` 模式的像素起点 = `sync_end + porch`；Scottie 族因同步在行中，需要 `−chan_len/2 + 2×porch` 的修正（slowrx `skip_correction_seconds`）。

### 4.6 像素采样与色彩空间

- 每个像素取其时间窗 `[t, t+pixel_µs)` 内 `f(t)` 的**均值**（而非中点单值）→ 抗噪。
- 频率 → 亮度：`v = (f − 1500) / (2300 − 1500)`，钳制到 `[0,1]`，再 ×255。
- **异常值处理**：若窗内频率方差过大（含同步脉冲/静音），标记该像素为无效，用邻行同位置像素补（避免黑线撕裂）。
- 色彩转换：
  - PD 族：YCrCb → RGB（`R = Y + 1.402(Cr−128)` 等），**注意 4:2:0 配对**：一对行的 Cr/Cb 来自同一无线行。
  - Robot 族：YUV，**奇偶行色度互补**：本行缺失的分量从上一行复制。
  - Martin/Scottie：直接 RGB，无需转换。
- 「图像发绿」的典型成因：Cr/Cb 顺序颠倒或行配对错位（PD）——建议把这两点写成单元测试。

### 4.7 实时成像与线程模型

| 线程 | 职责 |
|---|---|
| 音频线程（`THREAD_PRIORITY_AUDIO`） | `AudioRecord.read()` → 写入原始样本环形缓冲（照搬 `Ft8Recorder` 的 readThread 结构） |
| 解码线程（`Dispatchers.Default`） | 鉴频 → VIS → 行解码；每完成一行更新 `StateFlow<SstvUiState>` |
| UI 线程（Compose） | 观察状态流，增量重绘 Bitmap |

- 逐行刷新频率：PD-120 每 508 ms 出一对行、Robot 36 每 150 ms 出一行 —— 远低于 60 fps，**无需节流**。
- 内存：PD-120 一帧 640×496×4B ≈ 1.27 MB（ARGB_8888），可忽略。
- **不要每行重建 Bitmap**：创建一次可变 Bitmap，用 `setPixels` 局部更新 + 递增版本号触发 Compose 重绘。

### 4.8 精度预算

| 环节 | 误差 | 对图像的影响 |
|---|---|---|
| 频率估计误差 ±1 Hz | — | 亮度误差 ≈ `1/800 × 255` = **0.32 级** |
| 目标：亮度误差 ≤ 2 级 | ±6 Hz | 需信噪比 ≥ ~15 dB（FM 鉴频输出） |
| 像素时间抖动 | ±1 样本 @48 kHz = ±21 µs | 占 PD120 像素的 11% → 需均值采样抑制 |
| 行周期误差 1% | 每行偏移 5 ms | 100 行后偏移 500 ms ≈ 一整行 → **必须 slant 校正** |

## 五、方案选型对比

### 5.1 技术路线

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **① 纯 Kotlin 自研** ⭐ | 零依赖；与 FT8/SGP4 路线一致；可精确控制到像素级；便于单元测试 | 需自研 FFT/滤波器（约 300 行） | ✅ **推荐** |
| ② 移植 robot36 的 C 代码（NDK） | 成熟、性能好 | 引入 NDK 构建复杂度；APK 体积 ↑；与项目纯 Kotlin 风格冲突 | ❌ |
| ③ 引入 Java 第三方 SSTV 库 | 省事 | 无成熟活跃的 Java/Android SSTV 库；引入未知维护风险 | ❌ 不可行 |
| ④ 服务端解码 | 手机零负担 | 违背 HamKit「随身控制台」定位；离线不可用 | ❌ |

> **robot36 为 CC0 公有领域**，可作为**算法对照实现**（阅读其 `buffer.c` / `utils.h` 的处理流程），但不搬运代码，保持纯 Kotlin 自研。

### 5.2 模式支持范围

| 阶段 | 模式 | 理由 |
|---|---|---|
| **一期 MVP** | **全部 11 个模式**：PD-120/180/240、Robot 24/36/72、Martin 1/2、Scottie 1/2/DX | PD 全族是 ISS 场景的核心（PD-120 为 ARISS 现行模式）；Robot/Martin/Scottie 覆盖 UV 段与 HF 最常见模式。四种组合（PD 帧 / Robot YUV / RGB 顺序-行首同步 / RGB 顺序-行中同步）全部实现 |
| **三期** | PD-50/90、B/W 模式、AVT 系列、盲扫自动模式判定（VIS 丢失时靠同步间隔反推） | 需补充参数查证与启发式逻辑 |

> **模式范围的两次调整**：初版建议一期做 4 个模式 → 核对 slowrx 源码后扩大到「PD + Robot + Martin 全族」（同族只是同一公式的参数实例，增量成本几乎为零）→ 补查 `mode_scottie.rs` 后**再纳入 Scottie 全族**，最终一期即支持全部 11 个模式。
> Scottie 的障碍曾被高估：其行布局 `[sep][G][sep][B][SYNC][porch][R]` 有权威依据，行首反推只是「扣掉 `2·sep + 2·chanLen`」一行公式，详见 §11.6。

### 5.3 编码（发射）方向：**建议一期就做，但定位为测试基础设施**

| 用途 | 价值 |
|---|---|
| **自环测试**（金标准） | 生成已知图像 → 编码为音频 → 解码 → 与原图对比 PSNR。这是唯一能脱离真实电波验证解码正确性的手段 |
| 实际发射 | 手机对电台麦克风发射图片，与 CW/FT8 的播放能力定位一致（`Ft8SettingsStore.txEnabled` 说明项目并不排斥发射功能） |
| 工作量 | 极小：模式表 + 频率映射 + AudioTrack 播放，约 150 行，与解码器共用模式参数表 |

→ **一期实现编码器（仅用于测试与预览），发射 UI 放二期**。

### 5.4 输入源

| 源 | 一期 | 说明 |
|---|---|---|
| 麦克风实时 | ✅ | 主场景；照搬 `Ft8Recorder` |
| WAV 文件导入 | ✅ 建议 | 实现成本低（PCM 读取），且是**测试与调试的刚需**；用户录下通联音频可离线解码 |

### 11.2 实现阶段证伪的四个「想当然」

| # | 初版设想 | 实测结果 | 最终方案 |
|---|---|---|---|
| 1 | 低通用 2 阶 Butterworth、截止 600 Hz | 无噪声下 RMS 竟达 **41.7 Hz**（与信噪比无关）：信号接近中心频率时基带 I 分量趋近 0，2f₀ 镜像残留（−32 dB）被放大成相位抖动 | **8 阶 + 1200 Hz**：3800 Hz 处 −80 dB，RMS 降到 **0.15 Hz**，同时调制带宽翻倍（水平过渡带缩短一半） |
| 2 | 逐像素按 `round(像素时长 × 采样率)` 生成样本 | PD-120 单像素 9.12 样本被舍入成 9，640 像素短 76.8 样本，累计每行短 6.4 ms（1.3%）：图像整行水平错位，自环 PSNR 仅 11.8 dB | **时间累加器**：以理论时间轴计算目标样本位置，舍入误差不随像素数累积，PSNR 恢复到 25–56 dB |
| 3 | 解调滤波器的群延迟需要补偿 | 扫描 −20…+60 样本，**0 最优**（补偿 32.6 样本反而使 PSNR 从 29.9 掉到 14.9 dB） | 行同步是在同一条「已被延迟」的频率流上检测的，同步位置与像素采样共享同一时间轴，**无需补偿** |
| 4 | 失谐量取 VIS leader 的实测频率 | leader 只有 300 ms 观察时间，残余偏差会整体抬高/压低亮度 | 改用**全部行同步脉冲的平均频率**（PD-120 有 248 个脉冲），统计误差可忽略 |

### 11.3 实测性能

**鉴频精度**（48 kHz，无噪声）：

| 指标 | 实测 |
|---|---|
| 恒定频率（1200/1500/1900/2100/2300 Hz）估计误差 | **< 0.05 Hz** |
| 无噪声像素级 RMS（PD-120 像素窗） | **0.148 Hz** |
| 10 ms 频率阶梯最大误差 | 0.34 Hz |
| SNR 30 / 25 / 20 / 15 dB 的像素级 RMS | 1.9 / 3.4 / 6.1 / 10.8 Hz（≈1–3 级亮度） |

**编解码自环 PSNR**（24 位彩色，与原图逐像素比对）：

| 内容类型 | 全图 | 主体（去每行首尾 10 像素） |
|---|---|---|
| 平坦纯色 | 28–35 dB | **52–56 dB** |
| 正弦渐变（1 周期/行） | 29.8 dB | **51.9 dB** |
| 正弦渐变（4 周期/行） | 30.1 dB | **43.6 dB** |
| 8 色条（含 7 个尖锐边界） | 25.7 dB | 27.4 dB |
| 时钟漂移 ±1% | 22 dB | slant 拟合精确为 0.9900 / 1.0100 |

**结论**：图像主体可高保真还原（43–56 dB）；剩余误差来自两处**物理限制**，非实现缺陷：

1. **每行首尾约 1–2 个像素**必然落在「同步脉冲 / porch / 分隔脉冲 ↔ 图像」的频率过渡带上（坏像素占比实测 1.8–2.1%）；
2. **尖锐的水平边界**（如色条）超出模拟窄带模式的传输能力，任何解码器都无法完全还原 —— 用平滑内容验证时主体 PSNR 达 43–56 dB 即为明证。

### 11.6 Scottie 族的补入（原列二期，现已支持）

Scottie 曾是唯一被排除的族，理由是「同步脉冲位于行中，需要独立的对齐模型」。补查
[slowrx `mode_scottie.rs`](https://docs.rs/slowrx/latest/src/slowrx/mode_scottie.rs.html) 后确认：**该判断被高估了**，实际只是一个偏移量的问题。

**权威行布局**（slowrx `mode_scottie.rs:15-29`）：
```
[sep][G pixels][sep][B pixels][SYNC][porch][R pixels]
  ^
  line start
```

**据此修正的两处偏差**：

| # | 问题 | 后果 | 修正 |
|---|---|---|---|
| 1 | 原实现把 G 的起点当作 0，**漏掉行首那个分隔脉冲** | 整行相位偏 1 个 sep（Scottie 1 为 1.5 ms ≈ 3.5 像素水平错位）。自环测试发现不了（编解码同模型会自洽），但解真实信号会歪 | `channelTasks()` 的 Scottie 分支改为 `G = sep`、`B = 2·sep + chanLen`、`R = 2·sep + 2·chanLen + sync + porch` |
| 2 | modespec 给 Scottie 1/DX 的像素时长是 4 位近似值（432.0 / 1080.53 µs） | 「3 通道 + 2 分隔 + sync + porch」与行周期不符：Scottie 1 短 0.16 ms，**Scottie DX 超长 0.5 ms** | 按行周期反推精确值（Scottie 2 的标称值本身精确，保持不变） |

**实现方式**（四族统一，无特例分支）：

- **解码**：`SstvMode.syncOffsetSeconds` 给出「同步起点 − 行首」的距离（Scottie 为 `2·sep + 2·chanLen`，其余族为 0），`SstvSync` 用它把实测同步位置反推回行首；
- **编码**：新增 `SstvMode.lineEvents()`，以**写入顺序**描述一行（`Sync` / `Gap` / `Channel` 三种事件），编码器遍历即可 —— Scottie 的「同步夹在 B 与 R 之间」由此自然表达，无需在编码器里写 `if (Scottie)`；
- **不变量**：`lineEvents()` 累加出的通道起点必须与 `channelTasks()` 的 `startSeconds` **逐一相等**，该等价性由单元测试守护 —— 这是编解码不会时序漂移的根本保证。

**验证**：新增「Scottie 的同步脉冲位于行中」「lineEvents 与 channelTasks 的时间轴严格一致」「Scottie 族自环保真」等用例，测试总数 25 → 27，全部通过。

### 11.7 UI 与状态机侧的缺陷修复

信号处理链路之外（界面、状态流转、采集编排）做了一轮针对性检查，发现并修复 6 处缺陷。

| # | 缺陷 | 后果 | 修复 |
|---|---|---|---|
| 1 | 卫星详情页的预置模式写入了 `SstvSettingsStore` | 从 ISS 页面进入一次后，**首页再进 SSTV 也会一直是手动 PD-120**，自动识别悄悄失效且无从察觉 | 预置改为 `presetOverride` **页面级临时覆盖**，不落盘；用户手动选择任意模式即取消预置 |
| 2 | 帧缓冲无上限，且没有「收满即停」 | PD-120 一帧 24 MB、ISS 连发多张，加上扩容瞬间翻倍 → OOM 风险 | 收满一帧即停止采集并释放；另设 300 秒（覆盖 PD-240）硬上限兜底 |
| 3 | 部分解码每轮都从头解调整段音频 | O(n²)：一帧内累计解调约 15 倍单帧样本量，后期 CPU 占用约 25%，并反复制造 24 MB 临时数组 | 降频器改为**有状态增量解调**（只处理新增音频），频率流增量追加；解调后的原始音频即时压缩丢弃 |
| 4 | 自动保存用 `savedName == null` 当「未保存」标志 | 保存失败时标志永远为 null → 收满后**每 4 秒重写一次文件** | 新增独立的 `autoSaveAttempted` 标志，一帧只尝试一次，失败提示手动重试 |
| 5 | 接收中切换模式不生效、UI 也不提示 | 用户以为已切换，实际整个会话仍用旧模式 | 明确提示「将在下次接收时生效」（模式在启动时已固化进采集器） |
| 6 | 设置页在 Composable 里直接列图库文件 | 主线程文件 IO；且以 `status` 为 remember key，接收中会反复触发 | 图库数量移入 `SstvUiState`，由 ViewModel 在协程中刷新 |

另外：`lastResult` 由采集协程写、UI 线程读，补 `@Volatile`；`stopReceiving` 的文案在只收到部分行时明确提示「未保存、可手动保存」。

**自查中引入并当场修掉的一个新缺陷**：增量管线改造后，若 VIS 识别出的是未录入模式表
的码（如 PD-50），主循环会反复重新侦听同一个 VIS 头（既停不下来也白耗 CPU）—— 补
`unsupportedVis` 标记后终止。

**第 7 项（补修）**：关闭「实时预览」后接收完成也不出图 —— 根因是该布尔开关同时承担了
两件事：「过程中要不要重建 Bitmap」（性能）与「结果能不能看见」（功能），而后者不该被前者
决定。修法是让预览只控制**过程刷新**，并把所有结束路径都补上兜底：

- 收满一帧：`needBitmap = livePreview || complete`（`complete` 判定提前到 Bitmap 计算之前）；
- 手动停止：若尚无图则用最近一次结果补建一张，让用户能看到已收到的部分；
- 设置页文案同步为「接收过程中逐行刷新画面；关闭可省电，收满仍会显示图像」，使开关语义与实际行为一致。

默认（预览开启）下体验与之前完全一致；关闭预览的用户仍保留全部省电收益（PD-120 过程中
少建 31 次 1.27 MB 位图），只是不会再出现「收完了却什么都看不到」。

### 12.2 与规划的偏差

| # | 规划 | 实际 | 原因 |
|---|---|---|---|
| 1 | T4 只列 PD-50/90 + Robot B/W | 一并加入 **PD-160 / PD-290** | 权威数据（`sstv` crate）同时给出了这两个模式的完整时序，边际成本几乎为零；补齐后 PD 族在 320/512/640/800 四个分辨率档位上连续 |
| 2 | —— | **AVT / Pasokon / Wraase 系列仍不收录** | 与规划「不做」清单一致：资料稀缺，收益低于查证成本 |
| 3 | T4 计划「Robot B/W 参数」 | Robot 8/24 B/W 取自 pySSTV；**Robot 12 B/W 为推导值** | pySSTV 只实现了 8/24 两档。`0x06` 的归属由 VIS 码交错规律（B/W 族 `02/06/0A` 与彩色族 `04/08/0C` 交错）与「320 宽 B/W 模式扫描时长固定 93 ms」共同确定，并满足 `(0.007+0.093)×120 = 12.000 s` 精确自洽；仍属**推断**，已在 `SstvMode` 的 KDoc 中显式标注 |
| 4 | T6 计划「按 SNR 分档选择 `phaseSpan`」 | 实现为**每帧探测一次、整帧冻结** | 相位差分会改变频率流的噪声特性；帧内切换会让同一帧的前后段噪声不一致。探测放在 VIS 侦听期（并行喂一个 `span = 1` 的探针），因此不需要额外音频 |
| 5 | T7 计划「坏行修复」 | 判定条件加严为「**接近纯黑**的均匀行」 | 最初的「任意均匀行」判据会把图像里正常的中灰/亮色横条一起替换掉。同步丢失时采到的是 1200 Hz（同步）或 1500 Hz（porch），必然映射为黑，因此以「黑」限定更精确（见 `SstvPostProcessTest` 的两个对偶用例） |
| 6 | T5 计划「对每个候选做一次试解码，取同步命中率最高 + 图像最平整者」 | 另加**黑电平间隙结构判据** | 实测发现：Martin 1（446.446 ms）与 Scottie 1（428.38 ms）只差 4.2%，落在拟合斜率闸门（0.95–1.05）内，且两者的**试解码图像都是平滑的**（错位只表现为水平压缩与整体位移），平整度分不开。二者的真正差别是**间隙在行内的分布**（Martin 三个间隙全在同步之后，Scottie 有两个在同步之前），据此可稳定区分 |
| 7 | T8 计划「过境提醒直达接收态」 | 首轮未接线；**第二轮（§12.6）已补齐** | 首轮未接线的原因：提醒链路改动会牵动提醒存储与权限，与那轮 SSTV 改动无耦合。首轮交付的是「连续接收 + 模式/失谐量保留」 |
| 8 | T8 计划「收满一帧后重新侦听下一个 VIS 头」 | 连续模式**保留模式、不重新侦听 VIS** | ARISS 连发时每张图用同一模式，保留模式可零等待接续；而重新侦听 VIS 有把图像内容里的偶然音调串成假 VIS 的风险。若两帧之间真的换了模式，手动锁定或重新接收即可（见 `SstvRecorder.restartForNextFrame` 的 KDoc） |
| 9 | T6 的迟滞控制器若每帧新建实例 | 改为**按模式跨帧复用** | 每帧新建会让决策退化成「以正常档为起点的单次阈值判断」，迟滞完全失效；连续接收时质量在边界附近抖动就会逐帧切换积分窗，图像清晰度整体跳动 |

### 12.3 关键技术决策

**1. 发射必须流式，且流式与整段必须逐样本等价。**
最长模式 PD-290 单帧 289 秒 = 13.9 M 样本（FloatArray 约 55 MB，转 16 位播放缓冲再加 28 MB）。
`SstvEncoder.encodeChunks` 按**无线行**切块（PD-120 每块约 24.4 k 样本 ≈ 95 KB），配合
`AudioTrack.MODE_STREAM` 的写阻塞背压，全程只驻留一块。为避免「测过的」与「播出去的」
不是同一段音频，`encodeChunks` 与 `encode` 共用同一个 `writeRadioLine()`/`closeLine()`，
并由单元测试断言两条路径**逐样本相等**。

**2. 盲扫的失谐量必须自带估计。**
一期的失谐量来自 VIS leader（300 ms 单次估计）。VIS 缺失后若不补这一环，同步脉冲会落在
1200 Hz 的 ±60 Hz 容差之外，任何候选都串不成链。做法是对 1000–1400 Hz 做 10 Hz 分箱直方图
取峰值（要求峰值箱同时满足「≥ 5 ms 音调」与「≥ 3× 箱均值」两个条件），实测在 +45 Hz 失谐下
误差 < 1 Hz。

**3. 增量 VIS + 质量探针（T11 的性能与体验）。**
一期每一轮都用**新建的**检测器对最近 3 秒音频全量重算（约 300 次 FFT / 500 ms），且绝大多数
hop 被反复计算。现在只保留一个检测器实例并只喂新增音频；未锁定 VIS 时的音频回看缓冲也从
3 秒降到 1 秒（只需覆盖「检测触发时刻」到「图像数据起点」的错位）。
同一路音频再喂一个 `span = 1` 的探针降频器，用其相位抖动给出**信号质量**（见
`SstvDemodulator.estimatedQualityDb`），既用于选积分窗，也直接显示在主界面 ——
用户终于能判断「要不要调整音量或手机位置」，而不是盲等。
状态文案也区分了「侦听 VIS / 正在接收 / 解码中（已采集 N 秒）」三个阶段。

**4. 后处理一律默认关闭，且永远保留原图。**
三项处理都不可逆。UI 在开启后同时提供「保存增强图」与「保存原图」，避免用户为了对比而反复
开关设置。

### 12.6 T8 遗留补齐：过境提醒直达 SSTV 接收态

> 补齐日期：2026-10-11 ｜ 规划依据：[SSTV_PHASE2_PLAN.md](SSTV_PHASE2_PLAN.md) T8
> 状态：**已实现**（编译 + 13 个新用例守护；真机点通知的端到端行为未验证，见文末）

**为什么单独一轮做。** 首轮把 T8 拆成「连续接收」与「提醒接线」两半，只交付了前者：提醒链路
要碰 `AlarmManager` 调度、通知权限与提醒存储，与 SSTV 解码侧没有耦合，混在一个 PR 里只会让
回归面变大。但连续接收落地后，缺的这一环就变成「提醒响了，用户还得自己找到 SSTV 页面再按下
开始」—— 而过境窗口只有几分钟。

**链路。** 从闹钟到开收，各段各改一处：

```
ReminderReceiver（已存在，AlarmManager 触发）
  └─ ReminderNotificationHelper.showPassReminder()
       ├─ SstvSatelliteLink.isSstvSatellite()     判定要不要给 SSTV 入口
       ├─ SstvSatelliteLink.presetModeNameFor()   决定预置哪个模式（ISS → PD-120）
       └─ SstvLaunchIntent.putLaunchRequest()     把「直达接收态」写进 Intent
            └─ MainActivity.consumeSstvLaunchIntent()（onCreate + onNewIntent 两处）
                 └─ pendingSstvLaunch（StateFlow，消费一次即清空）
                      └─ LaunchedEffect → navigator.push(Route.SstvMain(autoStart = true))
                           └─ SstvMainScreen：applyPreset() 后立即 startReceiving()
```

**四个刻意的取舍。**

1. **正文点击与动作按钮都直达接收态。** 部分 ROM 会把通知正文点击折叠成「打开应用」，
   动作按钮（`接收 SSTV`）是更稳的入口；两者行为一致，避免出现「点这里只打开、点那里才开收」
   这种要用户试错的区别。代价是只想看提醒的用户也会被带进接收态 —— 但过境提醒本就是用户
   为「收这一次」而设的，且 SSTV 页一键可停。
2. **预置模式由 `SstvSatelliteLink` 一处决定。** 详情页原本把 `25544` 与 `"PD_120"` 硬编码了
   两遍（Miuix 与 Material 两份实现，Material 那份还是魔法数字）。现在三处入口共用同一份规则，
   并由 `SstvSatelliteLinkTest` 额外守护「预置模式名必须真的存在于 `SstvMode` 表」—— 枚举改名
   造成的静默失效比崩溃更难查。
3. **`autoStart` 是路由参数，不是全局状态。** 从卫星详情页手动进入时它保持 false：只有过境
   提醒这一条路径会自动开收，用户自己点进 SSTV 时仍然自己按开始。
4. **权限不静默失败。** 未授予 `RECORD_AUDIO` 时走系统授权弹窗；用户拒绝则落回既有的
   `onPermissionDenied()` 提示，而不是进入「界面显示正在接收、实际收不到任何东西」的假状态。

**涉及文件**

| 类型 | 文件 |
|---|---|
| 新增 | `data/sstv/SstvSatelliteLink.kt`（判定与预置规则）、`data/sstv/SstvLaunchIntent.kt`（Intent 契约 + `SstvLaunchRequest`） |
| 新增测试 | `SstvSatelliteLinkTest.kt`（9 例，纯 JVM）、`SstvLaunchIntentTest.kt`（4 例，Robolectric） |
| 变更 | `data/reminder/ReminderNotificationHelper.kt`（SSTV 条件下写 extra 并加动作按钮）、`ui/MainActivity.kt`（Intent 解析 + 导航消费，顺带删掉从未被消费的 `intentState`）、`ui/navigation3/Routes.kt`（`SstvMain.autoStart`）、`ui/screen/sstv/SstvMainScreen.kt`（预置后自动开收）、`ui/screen/satellite/SatelliteDetailScreen.kt`、`ui/screen/satellite/SatelliteDetailMaterial.kt`（改用共享规则）、`res/values/strings.xml` |

**未验证项**：本次只做到「编译通过 + 单元测试覆盖判定规则与 Intent 契约」。「真机点通知 →
应用冷启动/热启动 → 进入 SSTV → 自动开收」这条端到端路径无条件验证。主要风险是厂商 ROM 对
后台启动 Activity 的限制（Android 10+ 有后台启动限制，用户主动点击通知属于允许的例外，
但定制 ROM 未必严格遵守）。首次上机验证应覆盖三种情况：应用已被杀（冷启动）、应用在后台、
应用正停留在 SSTV 页时再次点击通知。

### 14.2 关键技术决策

1. **频率缓冲改成「最近样本环 + 按帧保留的抽样历史」**（Q1 的核心）。
   调研给的两个方案各有缺陷：全内存动态数组在 PD-120 下每小时 1.7 亿样本；「解完即丢」
   会让 `finalize` 无法做非因果重解。折中方案是两段式 ——
   - 高频段：最近 8 个行周期的环形窗口（对齐到 2 的幂，绝对位置 → 环下标是常量换算）；
   - 低频段：按帧保留「行起点 → 帧尾」的频率，**超出预算后把最老的段步长翻倍**（时间跨度不变、精度下降）。
   实测结论：`finalize()` 仍与一期**逐像素一致**，实时路径完全不受抽样影响。
2. **回收点必须留一个完整行周期**。`consumedSamples()` 取「下一行行首 − 1 个行周期」，
   而不是「已解完那一行的行尾」：下一行要先**被检测到**同步脉冲才解得出，而逐行精调还会回读该行
   同步脉冲的中心（Scottie 族的同步在行中）。少留一个行周期就会整幅错位。
3. **构造参数顺序**：`onLine` 放在最后。Q1 增加 `maxSegments` 参数时若插在 `onLine` 前面，
   已有调用 `SstvStreamDecoder(rate, mode) { … }` 会编译失败（一次真实的回归）。
4. ~~**融合用中位数而不是均值**~~。~~调研实验二指出弱信号下未筛选的均值融合会**反噬**；中位数对「某帧局部错位」这类离群点不敏感，实测与加权均值同量级但不劣于单帧。~~（随 Q3–Q5 移除）
5. ~~**增益按实测残差估计，不用 √K 理论**。~~（随 Q3–Q5 移除）
6. **持续接收要求先锁定模式**。没有 VIS 就无从反推行周期；开一条永远解不出图的热麦克风
   比直接提示更糟。切换开关时**不自动重启**接收（两种状态机不可互换，静默重启会丢掉已收内容）。

### 14.4 已知限制

| 项 | 说明 |
|---|---|
| **真机验证** | 与一期/二期相同的限制：声学链路、AGC、真实 ISS 信号下的持续接收表现只能在真机验证。本轮的端到端证据是「编码 → 加噪 → 解调 → 解码」的纯 JVM 用例 |
| **中途 VIS 不改模式** | 中途捕到的 VIS 只用于收尾判定，不实时切换模式 —— 切换会让流水号断裂、已收内容与新模式行周期不匹配 |

| 术语 | 含义 |
|---|---|
| **VIS** | Vertical Interval Signalling，SSTV 帧首的模式标识数字头，共 910 ms |

| **Slant** | 因收发时钟不严格同源导致的图像整体斜率倾斜 |
