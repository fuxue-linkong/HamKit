### P1 — 发射链路

#### T3 SSTV 发射（图像 → 音频播放）

| 项 | 内容 |
|---|---|
| **目标** | 把手机当信号源：选一张图 → 编码成 SSTV 音频 → 对着电台话筒播放。可用于本地自测（另一台设备接收）、演示、QRP 通联 |
| **现状** | `SstvEncoder.encode()` 已能生成完整一帧的 `FloatArray`（含 VIS 头），但**只能整段生成** |
| **关键约束** | 最长模式 PD-240 单帧 248 秒 ≈ **11.9 M 样本**，`FloatArray` 约 47.6 MB，加上 `ShortArray` 转换会翻倍 —— **必须改为流式生成与播放**，不能整段驻留内存 |
| **方案** | ① 给 `SstvEncoder` 增加流式接口：`encodeChunks(source, mode): Sequence<FloatArray>`（内部按行或按固定块产出，复用现有 `lineEvents()` 逻辑与时间累加器）；② 新增 `data/sstv/SstvAudioPlayer.kt`：AudioTrack `MODE_STREAM`，边生成边 `write`，带进度回调与停止；③ UI：从图库或相册选图 → 预览 → 选择模式 → 发射页（倒计时、进度、停止） |
| **涉及文件** | `SstvEncoder.kt`、新增 `SstvAudioPlayer.kt`、新增 `ui/screen/sstv/SstvTxScreen.kt`、`Routes.kt`、`MainActivity.kt`、`SstvViewModel.kt` |
| **验收** | ① 发射 → 由本 App（另一台设备）或第三方解码器能正确还原图像；② PD-240（248 秒）全程内存峰值 < 100 MB；③ 可中途停止且 AudioTrack 正确释放；④ 发射中离开页面不泄漏 |
| **工作量** | 3 天（编码流式化 1 天 + 播放器 1 天 + UI 1 天） |

> **风险**：手机扬声器 → 电台话筒的声学链路失真（AGC、频响）会直接影响对方收到的画质。发射侧无法控制，建议同时提供"音频文件导出"作为替代（对方可线路输入）。

### P2 — 模式与自动识别扩展

#### T4 扩展模式参数（PD-50/90、Robot B/W、AVT）

| 项 | 内容 |
|---|---|
| **目标** | 覆盖剩余常见模式，尤其 PD-50/90（ISS 早期与部分卫星用过）与 B/W 模式（弱信号下更稳） |
| **现状** | `SstvMode.kt` 已录入 11 个模式；PD-50 (`0x5D`)、PD-90 (`0x63`) 的 VIS 码已知但时序未查证；Robot B/W 系列（`0x02/0x06/0x0A/0x0E`）与 AVT 系列参数缺失 |
| **方案** | ① 逐族补参数，方法沿用一期：以 slowrx `modespec.c` 为权威源，并用「行周期 = 各通道时长之和」反向验证自洽；② 黑白模式需在解码器加"单通道 → 灰度"的组装分支（`SstvChannelLayout` 增一个成员）；③ 注意 Robot 12 B/W (`0x06`) 的**奇校验**特例 —— 解码端已支持（`SstvVis` 中 `R12BW_VIS_CODE`），此时才会真正用到 |
| **涉及文件** | `SstvMode.kt`、`SstvDecoder.kt`（B/W 组装）、`SstvCodecTest.kt`（每个新模式一条自环用例） |
| **验收** | ① 每个新模式的「通道之和 ≤ 行周期」由单元测试守护；② 自环 PSNR 达到与同族既有模式相当的水平；③ VIS 表无重复码 |
| **工作量** | 1 天（参数为主，代码增量极小） |

> 一期已建立"参数表驱动"的架构，本任务的边际成本几乎只在查证参数。

#### T5 盲扫：VIS 失败时的自动模式判定

| 项 | 内容 |
|---|---|
| **目标** | VIS 头被噪声吃掉时（弱信号常见），仍能自动判定模式，而不是让用户手动试 |
| **现状** | VIS 识别失败即提示手动锁定（`SstvDecoder` 返回 Failure） |
| **方案** | 分层判定：① **行同步间隔**是最强的指纹 —— 各模式行周期互不相同（150 / 226.8 / 277.7 / 300 / 428.4 / 446.4 / 508.5 / 754.2 / 1000 / 1050.3 ms），实测同步脉冲间隔可直接聚到某个候选；② 用**通道结构**区分同族近邻（如 Robot 24 与 Robot 36 行周期相同，靠色度通道是否存在/位置区分；Martin 1 与 Scottie 1 靠同步是否在行首区分）；③ 对每个候选做一次试解码，取"同步命中率最高 + 图像最平整（相邻行差异最小）"者 |
| **涉及文件** | 新增 `SstvBlindScan.kt`、`SstvDecoder.kt`（候选试解入口）、`SstvRecorder.kt`、`SstvMainScreen.kt`（显示"盲扫候选"） |
| **验收** | ① 人为削掉 VIS 头后，11 个模式均能正确判定；② 判定结果与 `SstvVisDetector` 一致率 ≥ 90%（用一期自环素材批量验证）；③ 盲扫耗时 < 3 秒 |
| **工作量** | 1.5 天 |

### P3 — 接收质量增强

#### T6 弱信号自适应积分窗

| 项 | 内容 |
|---|---|
| **目标** | 弱信号下少出噪点。当前 `SstvDemodulator` 的相位差分间隔 `phaseSpan` 按像素时长固定（`recommendPhaseSpan`），没有利用"信号越弱越该多平均"这一自由度 |
| **现状** | 实测噪声性能：SNR 30/25/20/15 dB → 像素级 RMS 1.9 / 3.4 / 6.1 / 10.8 Hz（约 1–3 级亮度）。SNR 再低时误差按 `1/√N` 增长，而 N（积分长度）目前是常数 |
| **方案** | ① 新增轻量 SNR 估计（复用一期 demodulator 的基带幅度，或对频率流做滑动方差估计）；② 按 SNR 分档选择 `phaseSpan`：弱信号时增大 span（牺牲水平分辨率换信噪比），强信号时缩小；③ 加 1 dB 迟滞带避免在阈值附近抖动（slowrx 的 `window_idx_for_snr_with_hysteresis` 是同类做法） |
| **涉及文件** | `SstvDemodulator.kt`、`SstvDecoder.kt`、`SstvCodecTest.kt`（新增"弱信号下 RMS 随 SNR 降级更平缓"的用例） |
| **验收** | ① SNR 10 dB 下的像素级 RMS 比现状改善 ≥ 30%；② SNR 30 dB 下不退步；③ 强/弱信号切换时无可见的模式抖动 |
| **工作量** | 2 天 |

> 这是本期唯一需要动 DSP 核心的任务，需要重新跑一遍 28 个用例 + 自环 PSNR 防回归。

#### T7 图像后处理

| 项 | 内容 |
|---|---|
| **目标** | 改善弱信号成图的观感（一期自环已证明算法本身可达 43–56 dB，真实电波的差距主要来自噪声与声学链路） |
| **方案** | 可选后处理开关：① **直方图拉伸**（把实际亮度范围拉满，修复自动增益压缩导致的灰蒙蒙）；② **轻度中值/双边滤波**去脉冲噪点（注意不要糊掉 SSTV 本就有限的细节）；③ **坏行修复**（同步丢失导致的黑行，用相邻行插值） |
| **涉及文件** | 新增 `data/sstv/SstvPostProcess.kt`、`SstvSettingsStore.kt`（开关）、`SstvDecoder.kt`（可选接入点） |
| **验收** | ① 对同一段带噪录音，处理后主观质量提升且不引入明显伪影；② 默认关闭，开启后仍可保存"原始解码结果"；③ 处理耗时 < 200 ms/帧 |
| **工作量** | 1 天 |

### P4 — 卫星功能深度联动

#### T8 过境窗口自动开收 + 多帧连收

| 项 | 内容 |
|---|---|
| **目标** | 真正的"一键收图"：ISS 过境前自动准备、AOS 时开始接收、连发多张时自动接续下一帧 |

| **验收** | ① 模拟连续两帧输入，能自动产出两张图且不 OOM；② 过境提醒触发后能直接进入接收态并预置正确模式；③ 连续模式可随时退出 |

#### T10 修复 CI 单元测试门禁空跑

| 项 | 内容 |
|---|---|

| **验收** | ① CI 日志出现具体测试类与用例数；② 生成 `TEST-*.xml`；③ 故意让一个用例失败时 CI 必须变红 |
| **工作量** | 0.5 天 |

## 三、依赖关系与建议顺序

```
T1 图库 ──┐
T2 文件导入 ─┼─→ T9 真机验证（需要素材回放能力）
T10 CI 门禁 ─┘        ↑
                      │
```
